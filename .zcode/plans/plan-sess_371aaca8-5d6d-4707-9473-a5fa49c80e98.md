### Issue 1 — folder 内 widget 子节点不克隆（bug）
**文件**: `src/mainview/store/canvasStore.ts`

1. 改写 `cloneWidgetReferences`（:192）：让它递归处理 folder 节点的 `data.children`。对 `type === 'widget'` 的顶层节点照旧克隆；对 `type === 'folder'` 且 `data.children` 是数组的节点，遍历 children，对 `child.type === 'widget'` 的子项克隆其 `data.widgetId` 并替换。用一个递归 helper 处理（与 `collectWidgetIdsFromNodes` 的遍历结构对齐）。
2. 改 `pasteClipboard`（:1512）和 `duplicateSelected`（:1538）的闸门：把 `pasted.nodes.some(n => n.type === 'widget')` 换成"图中任意位置（含 folder children）是否存在 widget 引用"的检测。直接用一个内联递归检测函数（或复用 `collectWidgetIdsFromNodes` 思路），避免遗漏 folder-only-widget 场景。
3. clone 失败回退（Issue 10 的根因之一，:215 `record?.id ?? widgetId`）：本次先保留可见节点但改为生成一个新的空 widget 占位 id 较重，风险大；这里采用**最小修复**——保留现有回退但加 `toast.error` 提示克隆失败，让用户感知数据耦合。完整的 detached 占位留作后续。（Issue 10 的彻底修复依赖更大改动，本次按"先止血"处理并在计划中标注。）

**测试** (`canvasStore.test.ts`): 新增 `duplicateSelected clones widget backing records inside folder children`——构造一个 folder，其 children 含两个 widget 子项，duplicate 后断言 cloneWidgetMock 被调用 2 次、副本 folder children 的 widgetId 与原件不同。再新增 `pasteClipboard clones widget backing records inside folder children` 对应 paste 路径。

### Issue 2 — 导入缺失 widgets map 时残留外部 id（bug）
**文件**: `src/mainview/routes/index.tsx`（:618 `importCanvasExportDocument`）

1. 在 `for...of` 循环里，当 `sourceWidget` 缺失或 `createWidgetRecord` 失败而 `continue` 时，记录被跳过的 widgetId 到一个 `skippedWidgetIds: Set<string>`。
2. 循环结束后，如果 `skippedWidgetIds` 非空，`toast.warning` 报告跳过数量（例如 "Skipped N widget(s) that could not be imported."）。
3. 关键修复：在 `buildImportedCanvasPayload` 调用前/中，对引用了未映射（即 `widgetIdMap` 中没有）widget id 的节点**不导入该节点**。实现方式：给 `remapImportedWidgetData` / `buildImportedCanvasPayload` 增加一个"标记跳过"的能力——在 `buildImportedCanvasPayload` 过滤 rawNodes 时，对 `type === 'widget'` 且 `widgetId` 不在 `widgetIdMap` 中的节点直接跳过（不放入结果）；对 folder children 中同类情况，从 children 数组剔除该 child。这样不会让带外部 id 的节点上画布。

**测试**: 这个函数在 `routes/index.tsx` 内、依赖 hooks，较难单测。改为在 `src/mainview/lib/importCanvasFiles.test.ts` 或新建针对 `remapImportedWidgetData` 的测试不可行（函数未导出）。**折中方案**：将 `buildImportedCanvasPayload` 和 `remapImportedWidgetData` 抽到一个可测试的纯函数模块（如 `src/mainview/lib/canvasImport.ts`），导出后单测"缺 widgets map 时跳过 widget 节点"。这同时改善可测性。如果抽取改动过大，则退而仅加一个集成式测试在 index.test 不可行——所以采用抽取方案。

### Issue 5 — `saveWidgetNow` 无串行化导致并发丢更新（bug）
**文件**: `src/mainview/store/widgetStore.ts`

采用 renderer 端按 widgetId 串行化（不改动 bun 端 schema，风险最低）：
1. 新增模块级 `saveChains: Map<string, Promise<void>>`。
2. 改写 `saveWidgetNow`：取消该 widgetId 的 pending debounce timer（保留现有行为），取当前 record 快照，把实际 RPC 调用包成一个 promise，挂到 `saveChains` 的链尾（`prev.then(() => doSave(), prev => doSave()` 之类），保证同一 widgetId 的保存顺序执行；链完成后清理 map 项。
3. 这样后发起的保存会等前一个完成再执行，且始终用最新的 record 快照——避免乱序落盘。注意 `scheduleSave` 内部仍走 debounce，串行化只作用于真正发出的 `saveWidgetNow`。

**测试** (`widgetStore.test.ts`): 新增 `saveWidgetNow serializes concurrent saves for the same widget`——mock `rpcSaveWidget` 让其延迟 resolve，连续调用两次 `saveWidgetNow`，断言两次按顺序完成、第二次保存的 record 是最终版本（用记录调用顺序的 spy 验证）。

### Issue 6 — load/save 不校验 kind 与 data 形状（bug）
**文件**: `src/bun/widgets.ts`

1. 新增 `parseWidgetRecord(unknown): WidgetRecord | WidgetLoadError`：校验 `schema === WIDGET_SCHEMA`、`id` 非空字符串且合法、`kind ∈ {checklist,pomodoro,reminder}`、`data` 是对象，并按 kind 校验最小形状（checklist 需 `items` 数组、pomodoro 需 `timer` 对象与必需数值字段、reminder 需 `dueAt`/`status`/`timezone`）。校验失败返回 `{ id, error: 'corrupted' }`（id 未知时用传入候选或 'unknown'）。
2. `loadWidget`（:194）用 `parseWidgetRecord` 替换现有手写校验。
3. `saveWidget`（:224）写入前先 `parseWidgetRecord(widget)`，校验失败则 `throw`（bun 端 RPC handler 已 try/catch 返回 `{success:false}`）。这样坏数据无法落盘。
4. 校验函数导出以便单测。

**测试** (`src/bun/widgets.test.ts`): 新增多例——`parseWidgetRecord rejects unknown kind`、`rejects checklist without items array`、`accepts valid pomodoro`、`saveWidget throws for invalid payload`、`loadWidget returns corrupted for wrong-kind data`。
