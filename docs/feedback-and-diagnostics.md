# 用户反馈和崩溃诊断

GhostBoard 在设置的“反馈与诊断”中提供问题反馈、功能建议和其他反馈。用户可以选填联系邮箱、勾选附带日志，并在发送前预览日志。成功提交后显示服务端报告编号；失败时保留当前表单，重试使用同一个报告 UUID，避免网络超时造成重复入库。

桌面端通过 Bun 主进程提交报告，后端位于 `/Users/laogui/Projects/react-starter-kit`。诊断偏好保存在应用数据目录，因此切换工作区不会改变自动上传开关。首次使用默认开启自动崩溃上报，反馈附带日志默认不勾选。

## 开发和发布配置

开发版默认请求 `http://localhost:8787/api/v1`，与后端项目现有 `PORT=8787` 配置一致。需要使用其他地址时，在桌面项目环境变量中设置：

```dotenv
GHOSTBOARD_SUPPORT_API_URL=https://your-api.example.com/api/v1
```

`electrobun.config.ts` 会把该公开地址嵌入 Bun 主进程构建，运行时环境变量可以覆盖构建值。canary 和 stable 版本没有默认线上地址，构建时必须配置。线上地址要求 HTTPS，localhost 可使用 HTTP。请求不跟随重定向；服务地址应直接指向接收 API，避免把诊断数据发送到意外的域名。

后端新增 `db/migrations/0004_desktop_reports.sql`。发布时，先在目标环境执行迁移，再部署 API 和管理后台，最后构建带有服务地址的桌面版本。在后端项目执行对应环境的现有命令：

```sh
bun db:migrate                 # 开发环境
bun db:migrate:staging         # staging 环境
bun db:migrate:prod            # 生产环境
```

本次实现只在临时本地 PostgreSQL 中应用并验证了迁移，未修改已有服务数据库或部署线上服务。生产部署命令沿用后端项目既有的 API 和 app 发布流程。

## 接口和后台查看

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `POST /api/v1/feedback` | 提交分类、反馈内容、选填邮箱及日志 | 公开，无需桌面账户或许可证 |
| `POST /api/v1/crash-reports` | 提交错误详情和近期日志 | 公开 |
| tRPC `support.list` | 按类型、状态分页查询摘要 | 已登录的内部 staff |
| tRPC `support.detail` | 查看反馈、环境、错误堆栈和日志 | 已登录的内部 staff |
| tRPC `support.setStatus` | 标记待处理、已查看、已解决 | 已登录的内部 staff |

已有管理后台 `/admin/logs` 页面展示报告列表和详情。页面沿用 admin 和 developer 的访问范围，接口遵循后端已有 `staffProcedure` 权限验证；普通用户和匿名请求无法读取报告。列表不返回日志正文，只有详情请求返回日志。

报告包含客户端生成的 `reportId` UUID、`kind`、`occurredAt` 和 `app`。应用信息包括版本、构建哈希、发布渠道、系统、架构、系统版本和 Bun 版本。反馈使用 `category`、`message` 和选填 `email`；崩溃使用 `error.source`、`error.name`、`error.message` 和选填 `error.stack`。附带日志放在选填的 `diagnostics` 字段中。

服务端保存到 `desktop_report` 表，以 `reportId` 去重，并返回内部 `rpt_` 前缀编号。正文上限为 512 KiB，诊断日志上限为 128 KiB UTF-8，反馈内容最多 8000 字符。每个来源每小时最多接受 60 个新报告；重复 UUID 的重试不消耗新报告额度。额度检查使用事务锁，避免并发绕过限制。来源地址加盐哈希后仅用于额度统计，数据库不保留原始 IP。

## 日志和本地队列

默认目录是 `~/.ghostboard/{channel}/diagnostics/`；设置 `GHOSTBOARD_DATA_DIR` 时位于该目录下的 `diagnostics/`。

| 文件 | 内容 |
| --- | --- |
| `app.log`、`app.log.1` | JSONL 日志，每份约 512 KiB，轮转保留一份历史日志 |
| `preferences.json` | 应用级自动上传偏好 |
| `session-{pid}.json` | 进程会话信息，用于识别异常退出 |
| `pending/{reportId}.json` | 已落盘、等待上传的崩溃报告 |

目录权限为 0700，创建的日志和报告文件为 0600。日志记录主进程的 warn、error、info，以及界面的 warn、error。任意对象不会被展开序列化；Error 保留消息和堆栈，文本中的常见密钥、Authorization、许可证、邮箱、本机路径和 URL 路径会被过滤。日志不会读取笔记、画布、附件、工作区设置或 AI 凭据文件。过滤是规则式处理，不能保证识别任意自由文本中的私人信息，因此反馈页提供预览，并提醒用户检查内容。

每份报告最多附带最近 128 KiB 日志。崩溃队列最多保留 20 份报告，超过 14 天的待上传文件会清理。应用每分钟检查一次上传任务，失败时按指数退避重试，最长间隔一小时；服务端限流后等待一小时。下次启动也会重试本地队列。关闭自动上传会取消正在进行的请求并删除待上传报告，但不影响用户主动提交带日志的反馈。

服务端报告目前持续保存在 PostgreSQL 中，没有自动删除任务。如需固定保存期限，可按 `created_at` 加入后端定时清理；不要使用本地队列的 14 天期限推断服务端保存期限。

## 崩溃捕获范围

主进程未捕获异常、未处理 Promise 拒绝和启动失败会先同步保存错误报告，再退出；下次启动上传。界面通过全局 error、unhandledrejection、React 错误回调和路由错误页面记录异常，主进程接收后保存并尝试上传。同一错误在一分钟内去重，单会话限制非致命异常的报告数量；致命异常优先保留，本地队列仍最多 20 份。

正常退出会删除当前进程的会话文件。下次启动扫描遗留会话，仅把已经退出的进程作为异常退出处理，避免把另一个正在运行的应用实例误报。异常报告使用上一会话的应用信息和最后活动时间，附带当前保留的近期日志。

Electrobun 当前没有向应用暴露原生崩溃转储或 WebView 进程崩溃事件。因此本实现不能上传 OS 原生 dump，也无法仅凭会话文件区分 native crash、强制结束和断电；这类报告明确标记为 `UncleanExit`。原生崩溃的精确堆栈需要后续接入平台专用转储采集。
