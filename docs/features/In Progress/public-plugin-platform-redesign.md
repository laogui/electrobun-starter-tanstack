# GhostBoard 公开插件系统整改方案

> 状态：待开始（方案已编写，未实施、未验收）
>
> 日期：2026-09-07
>
> 修订：v2，将纯命令、独立面板、导入器与画布内容类型共同纳入首版；插件运行不再依赖卡片实例。
>
> 目标：外部开发者独立开发和分发插件；普通用户通过 URL 下载或本地压缩包安装，无需修改或编译 GhostBoard。
>
> 本文接替 [旧 RFC-2](../Backlog/third-party-extension-platform.md) 作为公开插件系统的实施设计。旧文档保留历史背景，其“等待外部需求后再立项”的前提不再适用。
>
> 本文中的包格式、SDK、CLI 和目录路径均为拟议契约，不代表当前已经实现或发布。运行容器必须通过 P0 实验后定型。

## 1. 产品目标与整改原则

### 1.1 必须交付的完整路径

开发者可以在 GhostBoard 仓库之外创建插件，通过开发模式调试，将目录打成 ZIP，上传到自己选择的文件托管服务，再把下载链接发给用户。用户粘贴链接或选择本地 ZIP，即可预览、安装、启用，并执行命令、打开面板、导入资料或创建画布内容。发布新版时不需要等待 GhostBoard 发布。插件可以不提供界面、不创建内容实例，也可以组合多种贡献。

首版公开发布必须包含：

1. URL 下载安装、本地 ZIP 导入、开发目录加载。
2. 安装预览、兼容检查、权限说明、安装失败恢复。
3. 动态发现与注册，不改 `registerBuiltins.ts`。
4. 插件隔离运行、实例持久化、卸载后内容保留。
5. URL 更新检查、手动 ZIP 升级、版本固定与受控回退。
6. 无构建 HTML/JavaScript 示例、可选框架模板、开发诊断和打包工具。
7. 独立仓库样例与跨版本验证，证明 SDK 足以完成真实插件。
8. 纯命令、独立面板、导入器、画布内容四类插件均有实际可用的注册、运行和停用路径。
9. 工作区选择与内容查询、受控批量修改、事件订阅和插件级存储；这些能力不要求 instanceId。

### 1.2 灵活性的具体含义

| 维度 | 支持的选择 | 宿主保持稳定的约束 |
| --- | --- | --- |
| 开发技术 | HTML/CSS/JavaScript；可选 TypeScript、React 或其他能产出静态 Web 文件的工具链 | 发布包自包含，不依赖宿主私有依赖 |
| 获取来源 | ZIP 直链、发布描述文件、本地 ZIP、开发目录；后续可添加目录源 | 所有正式安装走相同校验与事务 |
| 发布方式 | 任意合适的 HTTPS 静态托管、社区目录、私下文件分享 | 发布者身份、版本、包摘要可追溯 |
| 功能 | 首版命令、面板、菜单/工具栏入口、导入器、画布内容、设置、受限事件与调度 | 功能入口与访问能力分开组合，新种类通过能力版本演进 |
| 状态 | 简单对象与声明式投影；复杂类型可提供迁移和投影函数 | 状态只经宿主事务提交 |
| 预览 | 自动摘要卡；可选声明式图片预览；后续丰富截图 | 列表不为每项启动完整插件 |

灵活不等于直接开放主进程、任意文件路径或宿主 Store。宿主通过小而完整的接口隐藏安装、权限、保存和生命周期复杂性。

### 1.3 首版不承诺的能力

不提供原生二进制插件、安装脚本、任意 Shell、常驻无限制后台代码、自动安装插件依赖、付费市场。应用完全退出后不承诺调度实时执行，重启后按恢复规则处理。高级截图不阻塞第一版，缺省使用 Presentation。

编辑器底层扩展、自定义导出器、持续双向同步和跨插件服务留待后续独立设计；纯命令、独立面板和导入器不属于延期项。

## 2. 当前基础与整改缺口

以下为源码检查结果，不等于经过完整运行验证。

| 当前实现 | 可以复用的基础 | 必须整改的缺口 |
| --- | --- | --- |
| [静态内置注册](../../../src/mainview/extensions/registerBuiltins.ts) | 统一内容类型发现入口 | 没有包安装、发现、版本选择或外部加载 |
| [BuiltinCanvasType](../../../src/mainview/extensions/types.ts) | 尺寸、交互、投影、视图声明 | React 实现与数据逻辑耦合；创建流程是固定枚举 |
| [共享协议](../../../src/shared/extensions/protocol.ts) | 通用实例与宿主能力词汇 | 同步状态读取、能力审计声明不足以直接成为外部协议 |
| [Host API](../../../src/mainview/extensions/hostApi.ts) | 可收敛的宿主能力入口 | `network.fetch` 实为 unfurl，`assets.remove` 空实现，附件元数据依赖临时缓存 |
| [前端实例 Store](../../../src/mainview/store/extensionInstanceStore.ts) | 历史、批量加载、保存队列 | 版本条件未贯通、回包覆盖风险、无效状态仍可进入保存链 |
| [扩展节点](../../../src/mainview/extensions/ExtensionNode.tsx) | 通用外壳与 fallback | 校验失败后显示默认可编辑状态；数据迁移调用链需补齐 |
| [调度存储](../../../src/bun/extensions/scheduler.ts) | 持久化任务和到期计算 | 任务身份未按实例隔离，持续运行与到期投递闭环需补齐 |

继续沿用画布空间数据与实例数据分离、未知数据保留、禁用不删内容、纯文本投影和宿主统一外壳。不得因公开插件化而重写已有工作区格式或批量更改类型 ID。

## 3. 核心模型与版本关系

### 3.1 区分六个对象

- **PluginPackage**：不可变的一个发布包，由插件 ID、版本与包摘要共同标识。
- **InstalledPlugin**：本机已保存的包版本及获取来源，不表示已在所有工作区启用。
- **WorkspacePluginBinding**：工作区选用的版本、插件启用状态和授权。
- **Contribution**：插件注册的命令、面板、导入器或 Canvas Type 等；一个包可贡献多项，不能强制包含 Canvas Type。
- **Instance**：画布扩展类型的用户内容，继续持久化于工作区，与插件代码独立；纯工具和面板不需要假实例。
- **RuntimeSession**：某次执行会话，绑定工作区及具体操作或视图；可以销毁重建，不能作为用户数据来源。

插件自己的持久设置/业务数据、视图布局状态和画布实例 state 分开保存。通用资料通过 ContentRef 访问，不把 Note、附件、画布节点和 ExtensionInstance 强行转换成同一内部存储格式。

### 3.2 ID 与版本规则

插件 ID 使用类似 `community.alice.habit` 的稳定名称，不要求开发者购买域名。ID 是内容命名，不是身份证明。`ghostboard.*` 保留给内置插件；第三方不可覆盖。

Canvas Type ID 沿用 `${pluginId}/${localTypeId}`。内置现有 ID 原样保留，不因为目录调整改名。插件包版本使用语义版本；`manifestVersion`、`hostApi` 和各内容类型的 `dataVersion` 分别版本化，不能混为一个版本号。

同一工作区同一插件只激活一个版本；不同工作区可以固定不同版本。一个版本新增权限，不等于其他版本自动得到权限。并行打开工作区的执行上下文必须携带工作区身份。

依赖策略：首版将第三方库打包进插件，不提供插件间依赖解析。后续确需插件协作时，通过版本化服务贡献添加能力，不开放任意跨插件读写。

## 4. 建议模块结构

```text
URL / 本地 ZIP / 插件目录
             │
        PackageSource adapter
             │
     Installer：下载、校验、暂存、提交、恢复
             │
       PackageStore + 安装数据库
             │
       WorkspacePluginBinding
             │
    RuntimeManager + PermissionBroker
         ┌───┴────────────────┐
  BuiltinAdapter       SandboxedWebAdapter
         └───┬────────────────┘
      ContributionRegistry
             │
    命令 / 面板 / 导入器 / 菜单 / 画布 / 设置
             │
      HostServices（权限检查后的业务接口）
         ├── Workspace / Content / Events
         ├── PluginStorage / Jobs / Assets
         └── Canvas / InstanceRepository
```

Installer 对调用方只暴露准备、提交、取消、查询进度与恢复结果。URL 和 ZIP 是同一个 seam 上的两个 adapter；不分别创建两套安装模块。开发目录属于临时运行 adapter，不假装已安装正式版本。

RuntimeManager 隐藏会话创建、权限绑定、挂起、崩溃恢复。Registry 只登记贡献描述和可调用句柄，不再要求所有贡献都是宿主 React 组件。InstanceRepository 统一处理状态一致性，所有运行 adapter 使用同一保存规则。

贡献声明决定功能出现在哪里，权限决定它能读写什么，两者正交。Installer 不根据插件是否有画布类型走不同路径。命令、导入、面板和卡片复用 Content 模块访问资料；InstanceRepository 仅负责扩展实例，不成为所有插件的必经接口。

## 5. 插件包格式

### 5.1 压缩格式与目录布局

正式格式为 ZIP，同时接受 `.zip` 与 `.ghostboard-plugin` 扩展名，后者仅是便于关联应用的 ZIP 别名。首版不支持 RAR、7z、带密码 ZIP 或上传源码后在用户机器构建。

```text
habit-plugin.zip
├── ghostboard.plugin.json
├── index.html                # 仅有视图时需要
├── main.js                   # 界面脚本或无界面处理器
├── style.css                 # 可选
├── logic.js                  # 可选，迁移/投影/事件处理
├── assets/                   # 可选，包内静态资源
├── locales/                  # 可选，多语言文案
└── LICENSE                   # 建议
```

接受 manifest 位于包根，或所有有效内容统一包在一个顶层文件夹中的常见压缩方式。忽略受限的系统元数据目录；出现多个候选 manifest 时拒绝并说明位置，不猜测安装哪个插件。

上传压缩包在桌面产品中指本地导入，不把插件包或工作区数据上传到 GhostBoard 服务器。

### 5.2 最小 manifest 示例

```json
{
  "manifestVersion": 1,
  "id": "community.alice.habit",
  "name": "习惯打卡",
  "version": "1.0.0",
  "engines": { "hostApi": ">=1.0.0 <2.0.0" },
  "contributes": {
    "canvasTypes": [
      {
        "id": "habit",
        "name": "习惯打卡",
        "entry": "index.html",
        "dataVersion": 1,
        "initialState": { "title": "今日习惯", "count": 0 },
        "stateSchema": {
          "type": "object",
          "properties": {
            "title": { "type": "string", "maxLength": 256 },
            "count": { "type": "integer", "minimum": 0 }
          },
          "required": ["title", "count"],
          "additionalProperties": false
        },
        "presentation": {
          "titleField": "title",
          "textFields": ["count"]
        }
      }
    ]
  }
}
```

必填字段控制在身份、兼容范围和至少一个贡献。尺寸、图标、分类、创建流程、预览、权限都应有默认值。简单插件不必声明业务 schema；未声明时宿主只接受受限 JSON 对象，开发工具提示这是较弱校验。复杂插件可以提供明确 schema。

上例是画布类型包，不是所有插件的必填模板。纯命令包只需要 manifest 和一个 JavaScript 文件；没有 canvasTypes 时不要求 initialState、presentation、dataVersion 或 HTML。所有贡献局部 ID 在各自种类内唯一，宿主使用插件 ID 加局部 ID 防止冲突。

```json
{
  "manifestVersion": 1,
  "id": "community.alice.title-tools",
  "name": "标题整理",
  "version": "1.0.0",
  "engines": { "hostApi": ">=1.0.0 <2.0.0" },
  "permissions": {
    "required": [
      { "id": "content.selection.read", "reason": "读取选中资料的标题" },
      { "id": "content.selection.write", "reason": "整理选中资料的标题" }
    ]
  },
  "contributes": {
    "commands": [
      {
        "id": "normalize-titles",
        "name": "整理选中资料标题",
        "handler": "main.js#normalizeTitles",
        "when": "selection.hasContent"
      }
    ]
  }
}
```

`when` 取宿主公布的条件标识，不能执行任意表达式；`handler` 是包内模块路径加命名导出，按需在受限逻辑运行环境调用，不能直接 import 到主进程。权限声明本身不授予访问，命令执行时由宿主捕获选区并签发范围令牌。

### 5.3 可选声明

| 字段 | 含义与约束 |
| --- | --- |
| `description`、`author`、`homepage`、`license` | 展示信息；作者文本不等同于已验证身份 |
| `icon`、`locales`、`defaultLocale` | 包内资源与本地化；缺省图标、直接文本均可用 |
| `permissions` | 必需及可选权限，包含用途说明 |
| `updates.manifestUrl` | HTTPS 发布描述文件；用户安装时选择是否订阅 |
| `contributes.canvasTypes[].surface` | 默认/最小/最大尺寸、容器资格、详情入口 |
| `contributes.canvasTypes[].creation` | 直接创建、宿主表单或隔离创建页面 |
| `contributes.canvasTypes[].logic` | 无 DOM 的数据逻辑入口，运行于独立受限执行环境 |
| `contributes.commands` | 可无界面、无实例；声明 handler、名称和上下文条件，缺省进入命令面板 |
| `contributes.views` | 隔离 HTML 入口、标题、默认位置和单例策略；可在侧栏或主区域打开 |
| `contributes.menus` | 将已声明 command ID 放入受支持的右键菜单或工具栏，不重复定义处理器 |
| `contributes.importers` | 文件类型、解析 handler 和结果 schema；宿主提供选择、预览与提交 |
| `contributes.events` | 受支持的事件类型和 handler，用于按需唤醒；权限独立检查 |
| `contributes.settings` | 简单设置 schema 自动生成表单；复杂设置可用隔离页面 |

schema 禁止远程引用，限制深度、节点数和字符串长度。声明式投影只支持受限字段选择和格式选项，不接受表达式执行。未知普通元数据可保留；未知必需能力、权限和贡献种类必须拒绝或标记不兼容，不能静默忽略后执行。

## 6. URL 下载安装

### 6.1 支持范围

首版支持两种 URL：直接返回插件 ZIP 的 HTTPS URL；返回 `ghostboard-plugin-release/v1` JSON 的 HTTPS URL。链接是否以 `.zip` 结尾不是判断依据，允许有查询参数的下载地址。HTML 页面、代码仓库首页、需要交互登录的分享页、Git 仓库地址不能自动当作插件包。

用户粘贴不支持的页面时，提示“请使用压缩包直链或发布描述文件，也可以先下载 ZIP 再导入”。后续可添加特定托管服务的 Source adapter，通用安装器无需理解其网页结构。

下载请求不携带用户浏览器 Cookie、宿主登录态或插件运行权限。需要鉴权的私有来源首版使用用户取得的临时下载链接，或本地导入；专用凭据管理后续独立设计。

### 6.2 用户流程

1. 插件管理 → 从链接安装 → 粘贴 URL。
2. 显示“解析链接 / 下载中 / 检查安装包”与可取消进度；缺少总长度时显示已下载字节。
3. 本地暂存并读取 manifest，展示名称、版本、作者、来源域名、身份验证状态、权限、贡献种类和兼容结果。
4. 若本机有相同插件，明确显示“已安装 / 升级 / 降级 / 来源冲突”，不直接覆盖。
5. 用户确认安装；提交包后，为当前工作区选择启用和授权。其他工作区不自动启用。
6. 激活成功后按贡献显示“执行命令 / 打开面板 / 导入资料 / 添加到画布”；仅安装不自动执行业务动作或创建实例。

粘贴 URL 后可以自动执行只读下载和检查，运行插件必须发生在确认之后。插件说明、图标和 README 都按不可信内容处理，安装预览不执行包中 HTML/JavaScript。

### 6.3 下载规则

以下为拟定默认值，P0/P5 依据实际包和平台实验调整：压缩包 50 MiB、下载总时限 120 秒、无进度时限 20 秒、最多 5 次重定向。流式写临时文件并同步计算 SHA-256，不整包缓存在内存；实际字节达到限制即中止，不只相信响应头。

每次重定向重新检查协议和目标；禁止 HTTPS 降为 HTTP，不跨来源转发凭据。URL 中的 userinfo 拒绝，日志和安装记录中的查询凭据脱敏。一次性链接不自动成为长期更新源。

默认拒绝环回、链路本地、私网和本机服务目标，解析与实际连接都要验证，避免重定向或 DNS 变化绕过检查。企业内网需求通过用户明确添加的受信任来源例外支持：精确限定 scheme/host/port，首版可要求有效 HTTPS；插件不能自行创建例外。

首版取消后清理临时下载，重试从头开始。断点续传后续可加；若实现，必须绑定 ETag/Last-Modified 与包摘要，不能拼接不同版本响应。

## 7. 本地 ZIP 导入

入口包含“选择压缩包”与拖放到插件管理页；系统文件关联可作为后续便捷入口。首版一次处理一个包，多文件拖入时提示逐个安装，避免混合权限确认。

本地文件先复制到宿主暂存区，复制时执行大小限制与摘要计算，随后走与 URL 完全相同的包校验、预览、权限和安装事务。用户原始 ZIP 不修改、不移动；取消不会删除原文件。

离线导入不请求网络，不为验证作者或下载依赖而隐式联网。若包声明更新源，预览中可选择“以后检查更新”，默认关闭；未订阅时只支持手动导入新包升级。

拒绝损坏、加密、内容不完整或缺少所声明运行入口的包，并给出可操作原因。纯 JavaScript 处理器本身就是合法发布物；不能因没有 HTML 或构建目录而拒绝。错误需要指明文件或字段，例如“命令 handler 指向的 main.js 不存在”，不要只显示“安装失败”。

## 8. 共用安装事务与恢复

### 8.1 阶段与不变量

```text
acquiring → inspecting → awaiting-confirmation → staging
          → ready-to-commit → installed → activating → active
```

任何阶段都能进入 `cancelled` 或 `failed`。已安装与已激活分别记录：运行启动失败不伪装成下载失败。安装提交前不执行插件代码，已有可用版本不被原地修改。

每个安装事务有唯一 ID、插件候选身份、包摘要和 journal。按插件 ID 串行处理竞争安装；最终目录和状态库提交需采用可恢复的写入顺序。临时解包目录与包目录放在同一存储卷，避免假设跨卷移动是原子操作。

提交前检查剩余磁盘空间，计算包展开、旧版本保留和迁移备份的空间需求。`current` 选择通过原子更新的元数据表达，不依赖可被第三方包构造的符号链接。

### 8.2 包检查清单

- 防路径穿越：拒绝绝对路径、盘符、`..`、NUL、越界路径，以及规范化后重名的条目。
- 拒绝符号链接、硬链接、设备文件和其他特殊条目；目录创建与写文件也检查目标未被替换。
- 处理大小写不敏感文件系统和 Unicode 规范化碰撞，不按单一平台的路径规则验证所有包。
- 限制解压总量、条目数、单文件大小和压缩比；边解压边计数，不能只依赖 ZIP 目录声明。
- 初始默认：展开 200 MiB、5,000 条目、单文件 50 MiB、压缩比 100:1；超限明确拒绝，不能要求用户关闭全部校验。
- manifest 根路径唯一；所有入口和静态资源引用必须指向包内文件。
- 不运行 npm install、postinstall、Shell 或包提供的安装钩子；不递归解压包内压缩文件。
- 包结构、能力版本、摘要和身份策略校验完成后，才允许提交安装。

### 8.3 幂等与失败处理

| 场景 | 结果 |
| --- | --- |
| 同 ID、版本、摘要重复安装 | 提示已安装，可选择在当前工作区启用 |
| 同 ID、版本但摘要不同 | 视为重发冲突，要求新版本；开发目录不受此发布规则影响 |
| 断网、取消、解压失败 | 保留原可用安装；清理事务临时文件 |
| 包已提交但激活失败 | 标记失败并保留诊断；符合数据兼容条件时恢复旧绑定 |
| 安装中应用崩溃 | 下次启动按 journal 完成已提交事务或清理未提交临时产物 |
| 检查后文件被替换 | 提交前重新核对摘要，拒绝变更后的包 |

## 9. 来源、发布者身份与更新

### 9.1 降低发布门槛，不混淆身份

无需官方账号或付费证书即可手动安装未签名包。安装页明确标注“作者身份未验证”，权限仍由宿主执行。

SHA-256 证明字节是否匹配，不能单独证明作者身份。包内的 `author` 文本和插件 ID 也不能证明身份。拟采用可选的自签名发布密钥：工具自动生成密钥，公钥指纹代表连续发布身份，社区目录可以额外验证身份；密钥算法、规范化签名载荷和测试向量在 P0 固定。

签名放在发布描述文件或其 detached sidecar 中，对包含插件 ID、版本、hostApi 范围、包摘要和包 URL 的规范化载荷签名，避免要求包对自己的最终 ZIP 摘要签名。ZIP 可以独立手动安装；若无配套证明，按未验证来源处理。私钥不进入插件包。

第一次安装固定来源与可用公钥指纹。相同 ID 的不同发布者不得静默接管已有实例；转移发布者需要旧密钥签署换钥声明，或用户通过明确的来源替换流程确认，并重新审查权限。

### 9.2 发布描述文件示例

以下摘要占位值用于说明字段，正式生成器写入真实 64 位十六进制 SHA-256。

```json
{
  "schema": "ghostboard-plugin-release/v1",
  "pluginId": "community.alice.habit",
  "channel": "stable",
  "releases": [
    {
      "version": "1.1.0",
      "hostApi": ">=1.0.0 <2.0.0",
      "url": "https://plugins.example.com/habit/1.1.0/habit.zip",
      "sha256": "<64-hex-sha256>",
      "notes": "增加每周统计"
    }
  ]
}
```

描述文件最大 1 MiB；校验每条记录，下载后的 manifest 必须与候选记录身份及版本一致。使用多版本列表，使旧宿主能选择仍兼容的最新版本。变更日志按纯文本或受限 Markdown 渲染。签名字段作为可选的结构化证明附加，精确格式属于 P0 契约交付物。

### 9.3 更新策略

- 默认通知有更新，由用户决定安装；支持固定版本和关闭检查。
- 单纯 ZIP 直链不自动推导更新地址，也不把“latest.zip”反复变化当作可靠版本索引。
- 未签名包允许手动升级；有更新源时可提示候选，但每次确认。相同 HTTPS 域名不升级成已验证身份。
- 自动更新为用户选择项，只对身份连续、签名有效、无新增必需权限、兼容检查通过的来源启用；先下载暂存，在该工作区无未完成提交时激活。
- 新版本增加必需权限，暂停激活并展示差异；新增可选权限可保持未授权运行，功能应有降级。
- 从 URL 安装转到本地升级或反向切换时，重新核对发布身份；签名缺失不能默默降低已有身份保障。
- 下载源变化、更新源变化和公钥变化均作为来源变更单独展示，不允许新包自动修改信任记录。

### 9.4 回退与数据迁移

代码回退不等于数据回退。先检查旧版本能否读取当前 `dataVersion`；兼容则切换旧包，不兼容时保留当前数据并停用故障插件。只有用户明确选择恢复迁移前备份，才恢复旧数据，并说明迁移后修改可能不在备份中。

为每个工作区的版本激活记录迁移 journal 和实例原始备份。后台迁移采用限流批处理，单实例原子提交，可重启续跑；失败实例保留原始数据并隔离，不能用初始值覆盖。首次试运行完成前不写正式迁移结果。

## 10. 本地存储与工作区关系

```text
<app-data>/plugins/
  packages/<plugin-id>/<version>/<digest>/   # 不可变包内容
  staging/<transaction-id>/                 # 下载和解包暂存
  registry.json                            # 已安装包与脱敏来源
  journals/                                # 安装恢复记录
  dev/                                     # 开发目录映射，不复制项目源码

<workspace>/.ghostboard/
  plugins.json                             # 所选版本、启用、来源身份约束
  extensions.json                          # 沿用现有按内容类型禁用设置
  extension-instances/                      # 继续保存用户内容
  plugin-data/<plugin-id>/                  # 非敏感设置及受限工作区数据
  plugin-migrations/                       # 迁移日志与备份
```

授权记录保存在宿主本机管理存储，绑定本机工作区身份、插件发布身份和权限集合；不得因复制工作区里的 JSON 自动授权。敏感凭据放宿主凭据存储，只通过 opaque handle 使用，不写插件 state、导出文件或同步目录。

工作区保存插件版本要求与来源提示用于可移植性，但打开陌生工作区不自动联网下载或执行插件。显示“缺少插件”，用户可以从已知来源安装，或继续用摘要阅读和导出。面板恢复记录保留插件/视图 ID 与宿主验证过的布局信息；缺少插件时显示占位，不伪造内容实例。不能把工作区携带的 URL 当成可信安装命令。

## 11. 运行容器与协议

### 11.1 选择原则与 P0 门槛

首选验证 Sandboxed Web Runtime：视图发布物为自包含 Web 文件，无界面命令/事件/导入处理器为可直接执行的 JavaScript 模块。宿主分别提供受限视图容器与无 DOM 的逻辑执行环境，共用权限和消息协议，逻辑调用不要求创建可见页面。当前配置在 macOS/Linux/Windows 均为 `bundleCEF: false`，只能据此确定需要在各目标平台实测，不能推定它们具有同样的隔离和资源拦截能力。

P0 比较 sandbox iframe 与独立 WebView/受限执行进程方案，验证：

- 无法访问宿主 DOM、原生桥、其他插件资源和本地文件。
- 网络出口、子资源、跳转、表单、弹窗、Worker、WebSocket 等不能绕过声明的网络规则。
- 包内相对资源、模块加载与 opaque origin 场景可用。
- 中文输入法、焦点、快捷键、剪贴板和画布缩放行为可接受。
- 无限循环、消息风暴与内存增长时，宿主具备经验证的恢复手段。

不得把 iframe 直接等同于 CPU/内存隔离；宿主 UI 无响应时，同线程心跳和限频未必能救回。若首选方案不能满足不可信代码执行与恢复要求，必须采用经验证的更强容器后再公开开放。容器结果影响性能预算，但不能通过放开宿主原生桥来绕过。

### 11.2 协议契约

版本握手包含协议版本、宿主能力、插件/工作区绑定、上下文种类和 session epoch。instanceId 仅在实例上下文存在；操作上下文绑定 operationId 和授权范围，视图上下文绑定 viewSessionId。宿主生成每次会话的通信通道与身份，不信任消息体自报身份。opaque origin 时不能只靠 origin 判断发送者，必须绑定已知窗口/通道和会话随机值。

请求统一包含 `requestId`、方法、参数；响应为成功值或结构化错误。错误至少覆盖 `permission-denied`、`unsupported-capability`、`revision-conflict`、`invalid-state`、`resource-limit`、`cancelled`、`runtime-unavailable` 和 `persistence-failed`。

按方法定义超时、取消和幂等性；涉及写入的请求通过 operation ID 去重。宿主销毁会话后拒绝旧 epoch 的回包，取消在途请求，释放临时资源。

控制消息默认最大 256 KiB。实例状态上限沿用 1 MiB；大于控制消息上限的状态快照通过受限分块状态通道传输，整体校验后原子提交。SDK 封装分块，插件开发者不处理传输细节。图片、音频和大文件通过资产 handle，不放入状态消息。

### 11.3 生命周期

生命周期区分包安装、工作区激活、视图挂载、视图挂起、任务执行、停用和卸载。后台数据逻辑在隔离环境按需运行，不直接 import 到 Bun 主进程。离屏 Surface 可以销毁，实例状态和调度仍由宿主管理。

| 上下文 | 存续范围 | 可用内容 |
| --- | --- | --- |
| 插件工作区上下文 | 插件在该工作区启用期间的逻辑注册，不要求执行进程常驻 | 贡献注册、插件存储、获授权事件和任务 |
| 操作上下文 | 一次命令、导入或任务 | 捕获的选择、取消信号、操作 ID、临时资产、受限内容事务 |
| 视图上下文 | 一个侧栏/主区域面板或卡片视图 | 主题、尺寸、视图状态；仅卡片额外得到实例接口 |

声明式贡献在启用时登记，命令/事件处理器按需加载，面板首次打开时才创建容器。宿主集中管理注册项与 disposable 资源；挂载失败回收本次新增资源，热更新按插件与贡献 ID 替换，不重复注册。关闭面板只清理该视图的订阅，不注销整个插件的命令和后台订阅。

停用按“停止新调用 → 排空/取消操作 → 清理事件、任务和视图 → 注销贡献”执行；命令快捷键失效、菜单入口消失，布局占位和已保存数据保留。事件队列与任务是否恢复按各自契约处理，不能依赖 onunload 一定在崩溃时执行。

Canvas Surface 缺省使用宿主拖拽区；详情页面按需打开。停用会拒绝新能力调用、取消会话与未来调度，排空或显式报告已接受但未落盘的修改。程序启动支持插件安全模式，跳过第三方运行并允许用户停用故障插件。

## 12. 低门槛开发体验

### 12.1 路径 A：无需 Node/Bun、无需构建

开发者下载普通 Web 模板，编辑 manifest、HTML 和 JavaScript，在应用“开发插件 → 加载目录”中选择目录即可预览。模板可只需要三个文件，样式写在 HTML 或单独文件均可。宿主提供打包按钮，开发者无需安装命令行也能生成 ZIP。

模板入口按“工具命令 / 独立面板 / 文件导入 / 画布类型”组织。工具命令只编辑 manifest 和 JS，不要求创建 HTML；导入器只实现解析与数据映射，选择文件、进度和提交由宿主提供。

以下处理器与 §5.2 的标题整理 manifest 配套，接口为拟议契约：

```js
export async function normalizeTitles(ctx) {
  const items = await ctx.content.readSelection({ fields: ['title'] });
  const operations = items.map((item) => ({
    ref: item.ref,
    expectedRevision: item.revision,
    set: { title: item.title.trim().replace(/\s+/g, ' ') },
  }));
  if (operations.length === 0) return;
  await ctx.content.applyBatch({
    operationId: ctx.operationId,
    label: '整理资料标题',
    operations,
  });
}
```

宿主在调用前冻结选区并去重同一内容实体；不支持标题编辑的内容返回明确能力信息或在读取阶段说明不可操作项。命令不允许猜测任意 ref 扩大操作范围；批量操作默认全有或全无且作为一个可撤销操作。没有保存成功就不报告完成。冲突不静默重试有副作用的整条命令，用户可以刷新后重试。

以下是画布类型的拟议 SDK 使用示例，其中 `plugin.state` 仅在实例上下文可用；独立面板使用 `content` 查询与插件存储，不具有隐含的实例 state。宿主在隔离容器里先提供 `ghostboard` SDK facade，再启动插件入口；它不暴露宿主原生桥。浏览器单独打开页面时需使用开发预览器提供的 mock facade。

```html
<button id="add">完成一次</button>
<output id="count"></output>
<script type="module" src="main.js"></script>
```

```js
const plugin = await ghostboard.ready();
const output = document.querySelector('#count');
const button = document.querySelector('#add');

const unsubscribe = plugin.state.subscribe((state) => {
  output.textContent = String(state.count ?? 0);
});

button.addEventListener('click', async () => {
  try {
    await plugin.state.update((state) => ({
      ...state,
      count: (state.count ?? 0) + 1,
    }));
  } catch (error) {
    plugin.ui.showError(error);
  }
});

plugin.onDispose(unsubscribe);
```

`subscribe` 立即投递当前已准备好的状态。`update` 是 SDK 本地便利方法，内部读取 revision、计算下一份状态并提交；函数不通过消息桥传输。更新函数必须无副作用，冲突时 SDK 可刷新后有限次重试，重试耗尽显示冲突。默认 Promise 在宿主确认持久化后完成，SDK 可另提供保存状态与乐观展示订阅。

开发者不必自己生成实例 ID、写文件、实现 Undo、维护 Presentation 缓存或处理传输分块。简单插件按 manifest 字段生成投影，省掉 Canvas/Detail/Preview 三套视图的强制实现。

### 12.2 路径 B：可选工具链

提供原生 Web 与 React/TypeScript 模板，SDK 核心不绑定框架；React 只是可选 adapter。其他框架只要产出符合包契约的静态文件即可使用。

拟议命令如下，命令名需在实际发布前确认，不可将其写成当前已可用命令：

```text
npm create ghostboard-plugin@latest
npm run dev
npm run check
npm run pack
```

`dev` 提供独立浏览器预览和可选桌面连接；`check` 校验 manifest、入口、权限和状态样例；`pack` 输出可安装 ZIP、摘要与可选发布描述/签名。最终用户安装包时不执行上述命令。

开发连接使用用户主动配对和短期令牌，仅允许声明的本地端点；不允许任意网页扫描端口后调用开发桥。开发插件使用相同权限协议，默认连接测试工作区。使用真实工作区需显式切换，热更新不重置用户实例。

### 12.3 文档和工具验收目标

- 有基础 Web 知识的开发者通过模板在 15 分钟内完成可保存的第一个插件；这是待实测目标。
- 普通用户在 3 个主要操作内完成 ZIP 安装与首次使用：选择文件、确认、执行相应入口。
- 错误面板显示文件/字段、修复建议、运行日志和宿主拒绝原因；默认不收集工作区正文。
- 提供标题整理命令、工作区任务面板、CSV 导入器、Counter 卡片四类独立示例；网络和后台任务作为附加用例。
- SDK mock 明确标注不能代替真实权限、隔离、重启和保存测试。

## 13. 通用贡献与内容操作

### 13.1 首版贡献契约

| 贡献 | 注册内容 | 执行与清理规则 |
| --- | --- | --- |
| Command | 稳定 ID、名称、条件、handler | 命令面板/快捷键/菜单共用同一处理器，执行前检查上下文 |
| View | 稳定 ID、HTML 入口、默认侧栏或主区域位置、单例/多例 | 宿主控制容器、焦点和布局；不强制引用卡片，关闭时释放视图资源 |
| Menu placement | command ID、受支持位置、排序分组 | 只负责入口；不注入宿主 DOM，不修改其他插件菜单 |
| Importer | 扩展名/MIME、handler、结果版本 | 用户选择导入器；多个匹配不静默抢占，宿主处理预览与提交 |
| Canvas Type | 状态、投影、视图、空间约束 | 沿用实例持久化与画布外壳 |
| Settings / Events | 设置 schema、事件种类、handler | 分别受插件存储与事件授权控制，停用统一释放 |

一个任务插件可同时提供“选中内容转任务”的命令、任务侧栏和变化订阅。为同一动作添加工具栏入口不需要另一个插件，也不复制命令逻辑。每种贡献单独版本化；空的 canvasTypes 合法，空的全部贡献不合法。

### 13.2 宿主接口按能力划分

| 模块 | 责任 | 不能泄露的内部细节 |
| --- | --- | --- |
| `commands` / `views` | 执行动作、打开面板；动态创建句柄由 SDK 转换为协议 ID | 宿主 React 组件和任意方法调用 |
| `workspace` | 选择快照、导航、当前工作区上下文 | canvasStore、跨工作区对象引用 |
| `content` | 分页查询、读取已授权字段、创建、受控批量修改 | 文件布局、各旧类型私有字段 |
| `events` | 带类型的变更通知、取消订阅 | 任意事件名总线、未经授权的正文推送 |
| `storage` | 自身工作区业务数据和设置的限额持久化 | 其他插件命名空间、系统凭据 |
| `canvas` / `instance` | 放置内容、空间操作、卡片状态 | 要求所有插件拥有 instanceId |

模块按上下文和权限提供，能力不可用时返回结构化错误；不返回假成功或空实现。面板可申请工作区摘要查询，正文读取需要额外字段授权。纯命令缺省只能访问本次用户选中的范围。

### 13.3 ContentRef 与批量事务

ContentRef 是宿主签发的 opaque 引用，区分内容实体和画布上的放置位置。同一 Note 在多个画布出现时，编辑标题只修改一次实体；移动节点则必须提供 placement 引用。查询返回 revision 和支持的操作，不能要求插件判断旧节点类型分支。

首版支持读取摘要/标题/标签、按授权读取正文、创建基础资料、更新标题/标签和按许可修改正文。插件不能任意修改其他插件的私有 state；第三方类型的通用标题/标签只通过已声明的 adapter 操作，未支持的类型明确返回 unsupported-operation。

批量修改使用 `operationId`、各对象 `expectedRevision` 和宿主生成的历史标签。先验证所有目标和权限，再提交；首版批次拟定最多 100 个对象，超限由宿主交互引导分批。跨 sidecar 文件需持久化事务 journal、前像与崩溃恢复，读者不得看到半提交结果。该能力未完成时不能将循环单文件保存标记为原子批量操作。

用户命令形成一个宿主历史项，Undo 检查后续并发修改，不覆盖其他操作的较新结果。自动事件不抢占用户焦点历史，采用单独操作日志与可恢复记录。视图内临时筛选和布局不进入内容历史。

### 13.4 面板与事件

面板声明单例/多例、可停靠位置和恢复策略；布局状态由宿主保存，业务数据用插件 storage，二者都无需扩展实例。卸载后保留占位和设置，不把面板当成损坏卡片。

首版事件限定为选区变化、内容创建/修改/删除及工作区准备完成等有类型的事件。先持久化内容，再发送事件；携带 eventId、originPluginId、operationId、revision 和变更字段，正文需主动授权读取。支持批次合并、限频和循环保护，插件自身产生的事件默认过滤，禁止两个插件无界互相触发。

视图订阅是即时提示，挂起/重开后重新查询快照；插件级事件处理需要可靠执行时，使用宿主有界持久队列、游标和去重规则。队列溢出返回 resync-required 并重建查询，不能声称事件永不丢失。停用时撤销授权范围内的订阅和未执行处理器。

### 13.5 导入器

文件选择 → 匹配/选择导入器 → 受限解析 → 返回规范化资料和临时资产引用 → 宿主预览 → 用户确认 → 分批事务提交。解析阶段不允许直接写工作区；首版至少包含 CSV 到基础资料的映射，用户可以选择字段与目标画布。

宿主限制文件大小、解析时长、单批条数和结果总量；大输入流式解析，不要求整份文件塞进消息。取消前尚未提交的资料和临时资产全部释放；已确认的大导入采用多个显式批次，失败展示已完成数量和回滚入口，不假称全量原子。

恢复使用导入 operation ID 与批次 ID 去重。删除已导入内容前检查是否被用户后续编辑，冲突项保留并说明；不能为了回滚导入而删除新修改。导入成功的普通资料不依赖导入器继续安装。

### 13.6 画布类型作为可选贡献

将现有大对象内部组织为内容定义、视图定义和可选行为定义，并由单一注册入口组合。外部插件的贡献描述来自 manifest，行为函数通过隔离运行句柄调用。

创建支持三级：直接用 initialState、宿主按 schema 展示表单、插件提供隔离的创建页面。创建页面最终返回状态或取消；宿主校验后创建实例与画布节点，并将整个操作计入画布历史。选文件、输入 URL 等作为可复用宿主控件，不再让路由判断 `createFlow === 'image'`。

创建过程导入的资产先为临时引用，确认后归属实例；取消、崩溃或超时由宿主回收临时引用。不能出现选完文件取消创建后永久遗留资产。

菜单动作使用稳定 command ID、文字/图标和受限可见条件；执行时宿主重新验证上下文与权限。插件可以声明自己的动作，不能覆盖宿主删除、拖拽和历史规则。

后续扩展点可包含自定义导出器、编辑器底层增强或持续数据连接器；必须有真实场景、独立能力版本与访问范围。上述命令、侧栏/主区域面板、导入器与受限事件在首版实现，不以“预留贡献容器”代替交付。

## 14. 宿主能力与授权

| 能力 | 默认行为 | 授权后范围 |
| --- | --- | --- |
| 主题、尺寸、语言 | 按视图上下文可用 | 不授予内容读取 |
| 自身实例状态 | 仅实例上下文可用 | 当前绑定实例，其他上下文不提供 |
| 选中内容读写 | 命令声明权限并获用户授权 | 调用时冻结的 ContentRef 集合和字段，令牌随操作结束失效 |
| 工作区摘要/正文查询 | 分别声明并授权 | 分页、字段白名单、当前工作区；正文非隐式可读 |
| 工作区内容创建/修改 | 分别声明并授权 | 事务、配额和历史；不开放私有 state 任意写入 |
| 内容变化事件 | 声明并授权 | 仅已授权对象/字段的元数据，正文另行读取 |
| 插件设置 | 可用 | 自身命名空间，限额，不能读其他插件 |
| 文件选择与资产导入 | 用户操作时请求 | 用户选择的文件转为资产 handle |
| 资产读取 | 自身有效引用可用 | 不允许猜测路径读取其他内容 |
| 网络请求 | 默认关闭 | 按 HTTPS origin 授权；可选内网来源显式批准 |
| 外部链接 | 明确用户动作，经宿主校验 | 限定协议，打开前验证目标 |
| 通知、调度 | 显式声明并授权 | 绑定工作区/插件；仅实例任务额外绑定实例，限额 |
| 剪贴板、麦克风 | 显式声明，按操作请求 | 结合系统权限，不复用宿主已有授权绕过用户意图 |
| 其他插件私有数据、AI 凭据 | 首版不开放通用读取 | 内容投影按 content 授权，凭据后续走专用能力 |

网络请求与 `links.unfurl` 分开命名；请求方法、响应格式、重定向、字节上限和敏感请求头规则明确。沙箱不能通过直接浏览器网络接口绕过宿主代理，这属于 P0 验证门槛。

资产接口返回稳定元数据和受限 URL/handle，释放引用使用 `release` 语义；物理删除由宿主引用与 GC 决定。撤销、文库、回收站和迁移备份引用也必须计入保留集合。

授权按工作区与插件身份保存，必需/可选权限分开。插件安装页面用“读取你选择的文件”“访问 example.com”等文案说明用途。权限撤回即时影响后续调用，界面显示如何恢复或继续使用降级功能。

## 15. 状态、迁移、历史与投影

本节定义画布实例的强一致契约；通用内容批次按 §13.3 执行，插件工作区 storage 使用独立 revision、schemaVersion 和备份迁移，不要求 Presentation。插件版本激活同时检查实例 dataVersion 与插件存储版本；回退不得只检查卡片。仅有命令或面板也可能有需要保护的持久数据。

### 15.1 唯一提交路径

`验证会话 → 检查权限与 revision → 校验 state → 派生投影 → 原子持久化 → 确认新 revision → 广播快照`

所有写入按工作区/实例串行，revision 在持久化所有者处单调递增。不得把旧回包直接覆盖较新的前端草稿。普通编辑、菜单动作、后台事件和迁移都通过相同规则，但历史策略可不同。

UI 临时状态放插件视图内；对外不沿用容易混淆的 `history: ephemeral` 作为持久化开关。需要合并输入历史时用 edit group，宿主明确合并策略。保存失败给出用户可见状态；画布切换、停用和升级等待待保存修改完成或显示失败。

### 15.2 数据逻辑

简单插件使用 manifest 的初始状态、受限 schema 和字段投影。复杂插件可提供校验、迁移和投影逻辑，但这些逻辑只在受限无 DOM 执行环境运行，默认无网络/文件权限，限制执行时间与输出大小。宿主接管调用时机、输出验证和提交，禁止在主进程直接执行第三方函数。

状态与 Presentation 一起提交；派生失败时拒绝该次修改并保留上一版，不允许新状态配旧投影静默落盘。未知类型的导入与保留走不透明数据路径，不执行缺失插件的逻辑。

### 15.3 加载结果与 Undo

加载明确返回 available、disabled、missing-plugin、incompatible-data、corrupted 或 runtime-failed。版本过新和损坏均保留原始数据，不替换成初始状态。实例迁移按 dataVersion 有序执行，并有原始备份、幂等恢复和失败隔离。

沿用画布历史与内容历史的焦点分工，但 SDK 接管快捷键路由，插件不自行拦截宿主删除和全局 Undo。Undo/Redo 是产生新 revision 的内容变更，不把旧 revision 当作当前版本恢复。

### 15.4 搜索与只读预览

搜索、AI 基础上下文、导出和 fallback 只读取宿主已保存的受限 Presentation。未知或停用插件不影响这些基本读取路径。

首版自动生成摘要卡，可声明自身资产缩略图；不强制 PreviewSurface。文件夹和文库不启动每个实例的完整运行时。外部富预览和截图后续加入，并验证图像格式、大小和引用权限。

## 16. 后台任务

任务键由宿主组合工作区、插件、作用域和局部任务名；作用域为 plugin 或 instance，后者额外包含实例 ID。插件只提供局部名称和允许的作用域。同作用域同名任务采用 upsert，状态变化后协调取消旧任务。工作区日报等任务无需创建卡片；不能用到期时间作为全工作区唯一身份。

任务存储、到期扫描和通知独立于 Surface。应用运行且工作区被激活时执行；不要求对应画布可见。完全退出后不执行，重启或重新打开工作区时合并过期任务，并将 `missedCount` 和原始到期时间传给处理器。

到期任务先写入待投递记录，再唤起受限处理器，收到结果并提交状态/效果后标记完成。崩溃后可以重投；处理器使用 delivery ID，状态操作和通知使用幂等键避免重复。每日/每周任务必须保存时区策略，P0 固定夏令时和每月月末语义。

停用插件暂停/取消该插件任务；删除实例只影响该实例任务，不停止插件级任务。撤销恢复后由状态重新协调。升级暂停投递并排空在途任务，确认新版本后继续。通知与更新状态之间用宿主效果记录恢复，不让插件用 Surface 的 useEffect 猜测是否已经通知。

## 17. 插件管理界面

首版设置页包含“已安装”“安装插件”“开发插件”。轻量社区目录是可加的数据源，不是 URL/ZIP 安装的前置依赖。

已安装列表显示名称、所选版本、当前工作区状态、有无更新、来源、贡献种类和故障。详情页提供“执行命令 / 打开面板 / 导入 / 添加卡片”等适用入口，以及权限管理、版本固定、检查更新、手动升级、回退、日志、停用与卸载。纯工具不用显示卡片创建入口。

卸载默认仅移除代码与安装记录，不删除工作区实例、插件持久数据、导入结果或命令已经修改的资料。已提交命令的 Undo 依赖宿主历史，不依赖插件仍在运行。若包仍被其他工作区绑定或有运行会话，先列出影响并提供“仅在当前工作区停用”。涉及全局移除时需要明确操作范围；无法枚举离线/外部工作区时说明这一限制。

永久删除用户数据是独立操作，显示工作区与实例数量并单独确认。禁用、升级失败和卸载不得触发这一操作。运行错误卡提供查看详情、重试和停用，不无限自动重启。

内置类型暂时通过 BuiltinAdapter 保留原运行方式，逐项补齐共同契约；不要求一次性把全部内置 UI 搬进沙箱。先以无界面标题整理命令验证通用路径，再以独立任务面板、CSV 导入器和 Counter 验证组合能力；四者都不得要求修改宿主类型分支。

旧数据迁移、现有回归收尾和公开平台分阶段推进。不能把旧 RFC 的“声明存在”当作已实现保证；每条可复用契约需要测试证据。不重做已完成的旧行为迁移，也不强制用户将现有内置内容重新安装成第三方包。

## 19. 实施阶段、依赖与退出条件

所有阶段初始状态均为待开始。下表是交付范围，不是承诺工期；P0 完成后基于容器结果和实际缺口估算。

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| P0 契约与容器实验 | 四类贡献 manifest、三类上下文、签名载荷、逻辑/视图隔离原型、跨平台矩阵 | 无 HTML 命令与 Web 视图均可受控运行，不需要假 instanceId；隔离和失控恢复有实测结果 |
| P1 数据与动态注册基础 | ContentRef、批次事务/历史、插件 storage、InstanceRepository、版本迁移、贡献句柄 | 标题整理真实执行且可撤销；保存竞态与坏数据保护通过，不依赖静态注册源码 |
| P2 URL/ZIP 安装闭环 | 下载源、本地源、解包校验、安装事务、基础管理 UI | 在线/离线安装、取消、重启恢复、身份冲突和磁盘不足通过 |
| P3 外部运行与开发体验 | 四类模板、SDK、CLI、权限、面板、导入预览、事件、创建/详情/设置 | 命令/面板/导入器/卡片分别安装可用；侧栏不创建实例、导入可取消恢复、停用清理完整 |
| P4 更新、调度和迁移恢复 | 发布描述、手动升级、签名验证、更新策略、后台投递 | 升级/权限变化/不兼容数据/回退及任务重投矩阵通过 |
| P5 公开发布验收 | 性能与安全测试、中文开发指南、四类示例、支持诊断 | 两台干净机器完成“独立开发→URL/ZIP 安装→更新→卸载恢复” |

依赖主线：P0 → P1 → P2/P3 → P4 → P5。P2 的下载/解包部分可以在 P0 契约冻结后先行，P2 最终激活验收依赖 P3。P0 阶段就建立独立示例仓库，后续持续使用它验证，不能拖到 P5 才测试 SDK。

公开首版以 P5 为门槛。P2/P3 可用于内部预览，不能把“本地包已能显示”宣称为整个公开插件系统完成。

v2 增加内容批次事务、通用面板和导入器的实施成本，不能沿用仅卡片方案的隐含工期。若阶段需要缩减，先减少高级视图样式、附加工具链和复杂导入格式，保留四种基本形态的验收，避免再次退化为卡片框架。

## 20. 测试与性能验收

### 20.1 核心测试矩阵

| 类别 | 必测场景 |
| --- | --- |
| URL | 无扩展名直链、查询参数、描述文件、HTML 错链、重定向、超限、断网、取消、过期链接、内网拒绝及来源例外 |
| ZIP | 根目录/单层包裹、重复 manifest、损坏/加密、路径穿越、符号链接、大小写/Unicode 碰撞、解压炸弹、缺失入口 |
| 安装事务 | 同包重复、同版本异摘要、竞争安装、空间不足、每个阶段强制退出、提交后启动失败 |
| 身份更新 | 未签名首次安装、签名不匹配、换钥、来源切换、新增权限、固定版本、撤回版本、更新索引重放 |
| 数据 | 快速连续编辑、旧回包、冲突重试、保存失败、无效 schema、超过消息阈值的合法状态、迁移失败、过新数据、Undo/Redo |
| 生命周期 | 离屏、详情打开/关闭、跨画布、跨工作区、停用、卸载、重装、安全模式、旧 session 回包 |
| 权限 | 冒充实例/插件、读取其他资产、网络重定向逃逸、权限撤回、开发桥未配对访问、恶意工作区提示 |
| 调度 | 同时到期的不同实例、改期、删除/撤销、后台重投、应用退出恢复、升级排空、时区变化 |
| 可移植性 | 原生 Web 无构建、框架打包、离线运行、中文输入、多个目标桌面平台 |
| 无界面命令 | 不含 HTML/canvasTypes、未打开画布、选择冻结、同一资料多次放置去重、批量冲突、停用后 Undo |
| 独立面板 | 无 instanceId、单例/多例、关闭重开、布局恢复、订阅清理、工作区切换时拒绝旧数据 |
| 导入器 | 多个匹配、映射预览、用户取消、分批失败、重试去重、崩溃恢复、后续编辑后的回滚冲突 |
| 插件事件/存储 | 插件级任务、无视图运行、事件合并/自触发过滤/循环保护、队列溢出重同步、存储迁移与代码回退 |
| 通用内容权限 | 伪造 ContentRef、选区令牌过期、摘要越权读正文、事件泄露、拒绝私有 state 写入 |

更新索引不得使客户端自动退回已见过的旧版本；记录每个来源/通道的最高已见版本或签名序号，主动降级必须经用户确认。源撤回某版本只能停止推荐，不能远程静默删除用户的包和数据。

### 20.2 性能预算

沿用现有 500 节点/200 扩展的冷启动场景，并另建第三方运行时基线。记录机器、系统、宿主版本、实例状态大小和容器数，不能只报平均耗时。

拟定初始目标：普通 5 MiB 包的本地检查和安装在参考机器上 3 秒内完成；20 个轻量可见插件保持正常编辑；100 个第三方实例通过离屏挂起限制运行时数量；500 个仅需摘要的结果不启动 Surface。具体并发容器上限由 P0 测量决定。

额外记录大量已注册但未执行命令的启动成本、面板分页查询与事件风暴下的响应、导入期间宿主可交互性。未使用的命令和导入器不启动可视容器；这些预算独立于画布节点数量。

消息限频、处理时限、内存观测和崩溃熔断都必须有可观测结果。若所选容器不能提供每插件内存硬上限，文档应如实描述监测与隔离能力，不声称提供不存在的强制配额。

### 20.3 发布完成标准

1. 标题整理命令、独立任务面板、CSV 导入器、Counter 卡片四类样例在主仓库之外开发与构建，安装不修改主仓库文件。
2. 两台干净机器分别通过 URL 和本地 ZIP 完成安装，最终用户无需 Node/Bun。
3. 无构建插件完成创建、修改、保存、重启、搜索、导出和卸载后降级阅读。
4. 新版本分别通过 URL 与 ZIP 升级；身份冲突、权限增加和数据不兼容均无静默覆盖。
5. 不可信插件无法越权访问原生桥、其他插件数据或未授权网络。
6. 坏包、坏插件和失败迁移不破坏已有工作区；恢复路径有实机证据。
7. 文档的所有公开字段、SDK 方法和 CLI 命令与实际发布物一致。
8. 命令包只有 manifest 和 JS，执行批量修改并一次撤销；没有 HTML、canvasTypes 或伪造实例。
9. 任务面板通过授权查询现有资料，关闭面板后插件命令仍在，重开恢复布局并重新获取数据。
10. CSV 导入先预览后写入；取消不留未提交资料，恢复不重复导入，卸载导入器不影响已导入资料。
11. 同一组合插件注册命令、面板与菜单，入口复用同一命令；停用后所有注册与订阅消失，不影响其他插件。

## 21. 拟定决策与待实验项

已按本次用户目标确定的方向：URL 与 ZIP 同等支持；包独立分发；简单插件无需构建；账号与签名不作为手动安装前提；源开放；宿主统一数据和权限；更新与卸载恢复进入首版。v2 明确纯命令、独立面板、导入器和画布类型同为首版，贡献与权限正交，插件/操作/视图上下文分离。

P0 必须确定的工程细节：实际运行容器及资源协议、签名格式与密钥轮换测试向量、受限数据逻辑运行方式、schema 支持子集、调度时区语义、各平台最低支持版本与并发预算。这些是实施实验，不需要在写方案阶段把未经验证的实现选择伪装成定论。

社区目录可以随首版提供静态条目，也可以在首版后增加；URL、ZIP、更新描述和包身份协议不能依赖目录服务在线。官方账号、审核平台和交易系统不进入这次整改关键路径。

第一项实际实施任务是 P0：用只有 manifest 和 JS 的标题整理包，验证无界面受限执行、上下文授权和失控恢复，并固定最小命令契约；P1 接入真实批次修改与 Undo。同时验证独立 Web 面板容器。随后让这些包经本地 ZIP 和 URL 安装，再加入 CSV 导入和 Counter，逐步验证完整通用插件模型。
