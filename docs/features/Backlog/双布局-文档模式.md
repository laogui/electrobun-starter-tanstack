# GhostBoard 双布局：文档模式（Notion / Obsidian 风格）

> **作者**：规划稿　**状态**：Backlog　**优先级建议**：P1
> **关联**：[PRD.md](../../PRD.md) §视图与画布、[创意特性候选清单](./创意特性候选清单.md) 第 10 条「Folder 子画布 + Card Library」

---

## 1. 背景与动机

当前应用只有**画布模式**（XYFlow 实现，见 `src/mainview/routes/index.tsx`），所有节点（Card / Sticky / Folder / Group / Image）都自由摆放在二维平面上。这种形态适合**发散、可视化思考**，但在以下场景很弱：

- 长文写作 / 知识沉淀 → 用户想要一个**线性、聚焦**的编辑环境
- 大量笔记的**结构化浏览** → 卡片散落在画布上，找回成本高
- 习惯 Notion / Obsidian 的新用户 → 第一次进入画布会迷失

**目标**：在不破坏画布数据模型的前提下，**新增一种"文档模式"**，提供左侧目录树 + 右侧编辑器的传统布局，并允许用户在画布模式与文档模式之间随时切换，同一份数据两种视图。

---

## 2. 用户故事

1. 作为一个长文写作者，我希望在文档模式下专注地编辑一篇 Card 内容，不被画布上的其他元素干扰。
2. 作为一个知识管理用户，我希望左侧能看到所有 Folder 和 Card 的层级，点击即可打开。
3. 作为一个画布用户，我希望随时能切回画布模式，看到我刚刚在文档模式下编辑过的 Card 仍在原来的坐标上。
4. 作为一个新用户，我希望首次打开应用时能选择更熟悉的"文档模式"作为入口。

## 3. 范围

### 3.1 In Scope（首版必做）

- **顶部布局切换器**：在主窗口顶部增加 Segmented Control，可在「画布」/「文档」两种模式间切换，**当前 view 的数据保持不变**。
- **文档模式三栏布局**：
  - 左：目录树（Folder + Card + Image，支持折叠/展开）
  - 右：编辑器面板（复用现有 Tiptap，从 `FocusedView` 模态升格为常驻面板）
  - 顶部：面包屑 + 当前 view 选择器（继承 `ViewSwitcher`）
- **目录树交互**：
  - 单击节点 → 在右侧打开
  - 右键 → 复用画布右键菜单的子集（重命名 / 删除 / 移出文件夹）
  - 拖拽改变层级 / 排序（与 Folder 的 `data.children[]` 双向同步）
  - 新建 Card / Folder 按钮
- **数据一致性**：文档模式所做的所有改动（新增 / 删除 / 重命名 / 编辑正文 / 移动）走同一个 Zustand store + RPC 持久化，切回画布模式立即可见。
- **空状态**：当前 view 没有任何 Card / Folder 时，引导用户新建第一篇文档。

### 3.2 Out of Scope（首版不做，后续迭代）

- Sticky Note、Group、Edge 在文档模式中的展示（这些是纯画布概念，文档模式直接**忽略并保留**，切回画布时仍存在）
- 双向链接 `[[note]]` 与 Backlink 面板（已在创意清单 P1，独立特性）
- 标签 / Supertags
- 多文档分屏 / Tab
- 文档模式的搜索（首版复用现有 `Cmd+K` 全局搜索）
- 大纲 / TOC 面板
- 文档模式下的 Group 容器表达

## 4. 信息架构与数据模型

**核心原则：不新增持久化字段，把现有画布数据"投影"成树。**

| 画布概念 | 文档模式呈现 |
| --- | --- |
| `folder` 节点 | 树中的可展开文件夹，`data.children[]` 即子项 |
| `card` 节点（顶层） | 树根的叶子文档 |
| `card` 节点（在 folder 内） | 该 folder 子节点 |
| `image` 节点 | 树中的图片条目（点击进入只读预览） |
| `sticky` / `group` / `edge` | **不显示**，但保留在 store |
| `Group` 容器 | 首版忽略；可作为「分区」灰色虚线分组（P2 再做） |

**排序**：树内顺序需要稳定，新增 `order: number` 字段（可选），未提供时按节点的 `position.y → x` 推导。

**移动语义**：
- 把 Card A 拖到 Folder B → 等价于画布的 absorption（写入 `B.data.children`）
- 把 Card A 拖出 Folder → 等价于 `moveFolderChildToCanvas`（恢复为顶层节点，position 取 Folder 当前 position 偏移量）

## 6. 技术方案

### 6.1 路由与状态

- 在 `canvasStore` 增加 `layoutMode: 'canvas' | 'document'`，持久化到当前 view 的 manifest。
- `routes/index.tsx` 根据 `layoutMode` 渲染 `<CanvasView />` 或新增的 `<DocumentView />`。
- 切换不卸载 store，只切换 React 子树。

### 6.2 关键文件

| 新增 / 修改 | 路径 | 作用 |
| --- | --- | --- |
| 新增 | `src/mainview/components/document/DocumentView.tsx` | 三栏容器 |
| 新增 | `src/mainview/components/document/DocumentSidebar.tsx` | 目录树 |
| 新增 | `src/mainview/components/document/DocumentEditor.tsx` | 右侧编辑器（包 Tiptap） |
| 新增 | `src/mainview/components/document/useDocumentTree.ts` | 从 nodes 派生树 + 增删改 hook |
| 新增 | `src/mainview/components/layout/LayoutSwitcher.tsx` | 顶部 Segmented Control |
| 修改 | `src/mainview/store/canvasStore.ts` | 增加 `layoutMode` + selection；重用 `addFolderChild` / `moveFolderChildToCanvas` |
| 修改 | `src/mainview/components/canvas/FocusedView.tsx` | 抽取出可复用的 `<CardEditor />`，文档模式直接复用 |
| 修改 | `src/mainview/routes/index.tsx` | 根据 layoutMode 路由 |
| 修改 | `src/mainview/lib/canvasUtils.ts` | 新增 `nodesToTree(nodes)` 辅助 |

### 6.3 拖拽方案

左栏树拖拽建议用 `@dnd-kit/core`（轻量、与 React Flow 无冲突），不要复用 React Flow 的拖拽逻辑。

### 6.4 性能

- 树派生用 `useMemo`，依赖 `nodes` 引用。
- 大量节点（>500）时虚拟化（`react-virtuoso` 或 `@tanstack/react-virtual`，后者已是 TanStack 全家桶）。

## 7. 风险与权衡

| 风险 | 应对 |
| --- | --- |
| Sticky / Group / Edge 在文档模式不可见，用户误以为丢失 | 顶部模式切换时弹一次 toast：「画布上的便签和分组在文档模式下不显示，但已保留」 |
| 树排序与画布坐标双源 → 切回画布坐标错乱 | 排序仅在 folder 内严格生效；顶层 Card 的画布位置与树顺序解耦，互不影响 |
| Tiptap 模态升格为常驻 → 现有自动保存逻辑要适配 | 抽 `useCardEditor(cardId)` hook，FocusedView 与 DocumentEditor 共用 |
| 用户在文档模式删除一个 Card，画布上的连线（edge）变成悬空 | 删除节点时同步清理相关 edge（已有逻辑，确认覆盖）|
| 首版没有 Sticky 表达 → 重度便签用户不会切到文档模式 | 文档/画布定位本就互补，文档模式 v2 再考虑「便签收件箱」面板 |

## 11. 实现进度盘点（2026-05-17）

整体上 **核心骨架已落地，但若干「In Scope（首版必做）」项尚未实现**。

### ✅ 已实现

- **布局切换器**：`LayoutSwitcher`（`src/mainview/routes/__root.tsx`）已落在标题栏，画布/文档两模式可即时切换；状态保留（不卸载 store）。
- **store 支持**：`layoutMode`、`setLayoutMode`、`selectedDocumentId`、`documentSection` 都已在 `src/mainview/store/canvasStore.ts` 中。
- **持久化**：`useLayoutModePersistence`（`src/mainview/routes/index.tsx`）用 localStorage + `settings.defaultLayoutMode` 双层兜底。
- **三栏布局壳**：`DocumentView`（`src/mainview/components/document/DocumentView.tsx`）= `LeftRail` + `NoteList` + `DocumentEditor`，并兼容图片画廊模式。
- **路由切换**：`CanvasRoute`（`src/mainview/routes/index.tsx`）根据 `layoutMode` 渲染 `<DocumentView />` 或 `<CanvasComponent />`。
- **编辑器复用**：`DocumentEditor`（`src/mainview/components/document/DocumentEditor.tsx`）复用 Tiptap，支持笔记 / 图片 / 资产 / 链接四类。
- **新建 / 删除笔记**：`NoteList`（`src/mainview/components/document/NoteList.tsx`）支持新建（含 Folder 内）；`EditorToolbar` 支持删除。
- **键盘可达**：有专用 `useDocumentKeyboard`（`src/mainview/hooks/useDocumentKeyboard.ts`）；搜索面板兼容文档模式（自动切回并定位）。
- **数据一致性**：所有改动都走同一 store + RPC 持久化，切回画布模式立即可见。

### ❌ 未实现 / 缺失

| In-Scope 项 | 现状 |
| --- | --- |
| **真正的「目录树」**（折叠 / 展开 Folder → 列出其内 Card / Image） | `LeftRail` 只把 Folder 当作可点击的过滤标签（`folder:xxx`），点进去再在 `NoteList` 中显示子项；并不是 PRD 中「▾ 📁 / ▾ 📁 / • Card」的真正树结构 |
| **拖拽改变层级 / 排序**（PRD §6.3 指定 `@dnd-kit/core`） | `package.json` 与 `document/` 下都没有 `@dnd-kit`，`LeftRail` / `NoteList` 均无 `draggable` / `onDragStart`。**完全没做** |
| **右键菜单**（重命名 / 删除 / 移出 / 在画布定位） | `document/` 目录下 `onContextMenu` 零命中。**没做** |
| **重命名入口** | `NoteList` / `LeftRail` 中均无 rename UI |
| **面包屑**（PRD §3.1 顶部：面包屑 + ViewSwitcher 继承） | 仅 `EditorToolbar` 顶端用「类型 › 标题」一行模拟，没有真正可点击的面包屑路径，也没有沿用 `ViewSwitcher` |
| **首次进入 toast 提示**「Sticky / Group / Edge 在文档模式下不可见但已保留」 | 没看到该提示触发逻辑 |
| **虚拟化**（>500 节点时 `@tanstack/react-virtual`） | 未接入 |
| **图片节点在树中显示** | 树里没有，但图片有专门的 `ImageGallery` 段，等价但与 PRD 描述偏离 |

### 🔎 结论

- M1（壳）、M2（编辑器复用与选中态）、M4（持久化、键盘可达）基本完成。
- **M3 全部缺失**：树拖拽、移入 / 移出 Folder、右键菜单、重命名等核心交互都没做。
- M5 抛光中的「切模式 toast」也未实现。

可以认为：**「能看 / 能写 / 能切」已经可用，但 PRD 里强调的「Notion / Obsidian 风格的目录树管理体验」仍是半成品**。要补齐 §3.1 与验收标准第 2–5 条，主要工作量集中在 `LeftRail` / `NoteList` 的树重构 + `@dnd-kit` 拖拽 + 右键菜单 + 重命名。
