## GhostBoard 核心定位梳理

### 一、当前定位的模糊地带

项目里目前存在几种不同的自我描述，它们彼此并不矛盾，但各自指向不同的产品心智：

PRD 里的定义是"面向思考者、设计师和研究人员的视觉化个人知识库"，package.json 写的是 "a local-first spatial canvas for visual knowledge management"，市场分析里又把自己归入"本地空间思考工作台"。这三种说法分别强调了"知识库"、"画布工具"、"工作台"三个不同的品类归属。

品类归属决定了用户会拿你跟谁比较，也决定了他们用什么标准来评判你。这是定位里最核心的决策，不能含糊。

### 二、品类归属的判断

我的建议是：**不要把自己定位成"知识库"，也不要定位成"白板工具"，而是定位成"空间化思考工具"。**

原因如下。

**为什么不是"知识库"？** 知识库这个词暗示的核心价值是"存储和检索"。用户评价一个知识库好不好，标准是"找东西快不快"、"分类全不全"、"搜索准不准"。但 GhostBoard 的核心体验不是检索——你的核心体验是在无限画布上自由组织信息、通过空间位置建立关联。把产品定位成知识库，等于把最有差异化的部分（空间交互、动效、双分组模式）降级成了"附加功能"，而把搜索、分类这些基础能力推到了评判的前台。这对一个搜索功能都还没完全做好的产品来说，是给自己挖坑。

**为什么不是"白板工具"？** Miro、FigJam 这类白板工具的核心场景是多人协作、头脑风暴、会议工作坊。GhostBoard 是单人使用的桌面应用，没有实时协作。定位成白板，用户会期望看到协作功能，看不到就会失望。

**为什么是"空间化思考工具"？** 这个品类归属的好处是：它让用户的期望锚定在"思考"上，而不是"存储"或"协作"上。思考工具的评价标准是"它能不能帮我理清思路"、"它能不能帮我发现知识之间意想不到的关联"。这恰好是 GhostBoard 最擅长的场景——在画布上铺开信息碎片，通过拖拽、连线、分组来发现结构，通过缩放和聚焦在宏观与微观之间切换。

### 三、目标用户：收窄到"独立研究者与深度写作者"

PRD 里写的目标用户是"思考者、设计师和研究人员"，这个范围太宽了。"思考者"不是一个可操作的用户画像，几乎所有人都是思考者。

建议收窄为**独立研究者与深度写作者**。具体来说：

**核心画像一：独立研究者。** 包括博士生、独立研究员、咨询顾问。他们的工作流是：大量阅读 → 摘录和笔记 → 在信息之间建立关联 → 形成自己的观点或论文结构。他们最痛的问题是"读了很多但串不起来"——线性笔记无法表达信息之间的空间关系和层级结构。GhostBoard 的无限画布 + 连线 + Folder 堆叠恰好解决了这个问题。

**核心画像二：深度写作者。** 包括非虚构作者、技术写作者、内容创作者。他们的工作流是：收集素材 → 组织结构 → 写作输出。他们需要看到全局的素材分布，而不是一屏一屏地翻文档。GhostBoard 的多画布视图 + Group 分区 + 标签系统恰好支持这种"从混沌到有序"的组织过程。

**为什么排除设计师？** 设计师有 Figma、FigJam、Milanote 这些成熟工具，切换成本极高，而且设计师对协作有刚需。把设计师作为核心用户会导致产品路线图被协作需求绑架。当然，如果有设计师自发使用，欢迎他们，但不要把他们写进定位里。

### 四、核心痛点的一句话表述

"我有很多笔记和素材，但线性工具无法让我看到它们之间的关联和结构。"

这句话之所以重要，是因为它同时做了三件事：点明了痛苦（信息碎片化）、排除了竞品（线性工具不行）、暗示了解决方案的方向（空间化、可视化）。

### 五、差异化三角

GhostBoard 的三个核心差异点应该构成一个稳固的三角：

**角一：空间原生，不是插件。** Obsidian Canvas 是在一个笔记工具上加了个画布插件，画布体验是二等公民。GhostBoard 从第一天就为空间交互而生——无限缩放平移、语义缩放（ zoom out 看色块和标题、zoom in 看完整内容）、FLIP 动效的聚焦模式、双分组（Group 开放布局 vs Folder 堆叠收纳）。这些不是"功能清单上的条目"，而是"只有以画布为核心才能做到的体验"。

**角二：本地文件，不是数据库。** Heptabase、Scrintal 的体验也不错，但数据锁在云端数据库里。GhostBoard 的笔记就是 `.md` 文件，存在用户自己的磁盘上，不依赖任何服务。这意味着：离线可用、10年后仍然能打开、可以用任何编辑器修改、可以用 Git 做版本管理。"你的笔记是你的文件，不是我们的数据"——这在隐私意识觉醒的当下是一个强有力的承诺。

**角三：沉浸动效，不是功能堆砌。** 这是最难被竞品抄走的差异。GhostBoard 的动效不是装饰，而是认知的辅助——卡片从画布位置平滑放大到聚焦模式，让用户不会失去空间上下文；Folder 的堆叠展开动画让用户直觉地理解"这些卡片是从这个文件夹里出来的"。好的动效让工具变得"透明"，用户不再需要思考"这个弹窗是从哪来的"，而是自然地沉浸在内容中。

### 六、一句话定位（建议版本）

> **GhostBoard 是一款本地优先的空间化思考工具，帮助独立研究者和深度写作者在无限画布上发现知识的隐藏结构。**

这句话里每个词都有用意：

"本地优先"——直接亮出技术哲学，筛选出在意数据主权的用户，同时区别于 Heptabase/Scrintal 等云端产品。

"空间化思考工具"——品类归属，区别于笔记工具（Obsidian、Notion）和白板工具（Miro、FigJam）。

"独立研究者和深度写作者"——明确的目标用户，不是"所有人"。

"无限画布"——核心交互范式，让人立刻想象到铺开信息的场景。

"发现知识的隐藏结构"——价值承诺，不是"管理笔记"，而是"发现"——暗示这个工具能帮你看到你用线性方式看不到的东西。

### 七、备选定位版本

如果你觉得上面的版本过于"正式"，这里提供几个不同调性的变体：

**偏极简的版本：** "把笔记铺在画布上，让结构自己浮现。"

**偏技术感的版本：** "本地优先、Markdown 原生、空间驱动的个人思考环境。"

**偏感性的版本：** "你的思维是空间的，你的笔记工具也应该是。"

**偏行动导向的版本：** "别再一行一行地写笔记了——把它们铺开、连线、分组，看看会发生什么。"

### 八、定位与当前产品现状的差距

诚实讲，目前的产品状态和上述定位之间还有几个需要弥合的差距：

语义缩放（Semantic Zoom）是"空间原生"这个角的核心差异化特性，但 PRD 里明确标注了还未实现。如果这个功能做不好，"空间化思考工具"这个品类归属就少了一条腿。

首次使用体验（Onboarding）目前几乎为零。一个定位给"独立研究者"的产品，用户第一次打开时看到的应该是精心设计的引导流程——而不是一个空画布。研究者的时间成本高，第一印象不好就不会再回来。

搜索能力在 PRD 里标注为"MVP 但有覆盖缺失"。路线图 Phase 4 已经落地了搜索体验层的改善（高亮、分组、筛选 chips、搜索历史），但 Folder children 漏搜和 unlinked files 不可搜这两个覆盖硬缺口至今悬而未决。虽然定位不是"知识库"所以搜索不需要做到极致，但基本的"能找到东西"是任何工具的底线。

发布工程（构建、签名、自动更新）是完全的空白。一个本地优先的桌面工具如果连正式的安装包都提供不了，"本地优先"这个承诺就显得不可信。

### 九、定位的"不做什么"清单

好的定位不只是说"我是什么"，还要说"我不是什么"。以下是 GhostBoard 应该明确拒绝的方向：

不做实时多人协作。一旦做了，产品复杂度指数级上升，而且会改变产品的核心气质——从"安静的个人思考空间"变成"嘈杂的协作场所"。

不做 AI 自动生成内容。AI 可以辅助（比如自动标签、智能搜索、内容摘要），但 GhostBoard 不应该变成一个"AI 帮你写笔记"的工具。你的用户是有自主思考能力的研究者和写作者，他们要的是工具，不是代笔。

不做全平台。短期内专注 macOS（或 macOS + Windows），不要分散精力到移动端和 Web。空间交互在触控板/鼠标上的体验远优于触摸屏，这是产品形态决定的。

不做插件生态的过早投入。Obsidian 的插件生态很强，但那是在它有大量用户基础之后。现阶段每多一个插件接口，就多一份维护成本，而 GhostBoard 需要的是核心体验的极致打磨。
