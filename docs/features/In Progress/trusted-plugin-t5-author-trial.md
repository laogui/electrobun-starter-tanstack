# T5 外部作者试用协议

日期：2026-09-13（Asia/Singapore）  
适用：T5-6"外部作者试用"。目标来自 PRD §2.14.5——具备基础 Web 知识的开发者仅凭文档与模板在 15 分钟内完成第一个可用插件——以及[追加 1 §8](trusted-plugin-platform-addendum-1.md) T5 项："外部作者仅凭单文件参考与模板完成第一个插件，过程有记录；插件未使用任何宿主组件仍与宿主视觉一致"。结果记录在 [作者试用证据](trusted-plugin-t5-author-trial-evidence.md)。

## 1. 前置条件（缺一不得开始）

| 条件 | 来源 | 检查方式 |
| --- | --- | --- |
| `@ghostboard/sdk` 与 `create-ghostboard-plugin` 已发布到 npm | T5-1 `publish-sdk.yml` | `npm view @ghostboard/sdk version`、`npm view create-ghostboard-plugin version` 均返回 `0.1.x` |
| 文档站 `/docs` 与 `/zh/docs` 公开可访问，SDK 参考页由已发布 SDK 同步 | T5-3 | 浏览器打开 Start → "Build your first plugin"，Reference → SDK 页顶部 `sourceVersion` 等于 npm 版本 |
| 已签名应用发行包可下载安装（macOS arm64 / x64） | `release.yml` | 作者机器无 Gatekeeper 阻断地启动 |
| 四个公共样例包与 `index.json` 在公共 HTTPS 可下载 | T5-4 | `bun run test:plugin-t5` 至少在 arm64 通过 |
| 试用记录模板已准备 | 本文 §5 | 每位作者一份 |

试用期间**不得**把主仓库源码、内部证据文档或未发布的分支交给作者；作者只拿到文档站 URL、npm 包名与应用下载地址。

## 2. 招募

- 人数：至少 2 名，目标 3 名（允许一名因故退出）。
- 资格：会写 HTML / CSS / JavaScript，用过 npm 或 bun 安装依赖；**未**读过本仓库代码或参与过 T0–T4；未在 GhostBoard 团队工作。
- 记录每位作者：自评前端经验年限、是否用过 React、是否用过其他应用的插件系统（VS Code、Obsidian、Figma 等）、日常使用的 AI 编码工具（允许使用，但必须记录）。
- 设备：作者自己的 macOS 机器（arm64 或 x64 都可，记录型号）；Windows / Linux 作者不纳入，因为插件系统不支持。

## 3. 任务

给作者的材料只有三条：文档站 URL、"用 `bunx create-ghostboard-plugin` 开始"一句话、应用下载链接。主持人不回答任何技术问题，只记录提问；作者提问一律回答"请看文档"。

### 任务 1：15 分钟第一个命令插件（必做）

- 起点：应用已安装、Bun 已安装、终端已打开；计时从作者打开文档站首页开始。
- 终点：作者在应用命令入口中触发自己写的命令并看到效果（面板打开或内容变化）。自带模板的默认命令不算，作者必须至少改一个命令标题或行为。
- 记录：起止时间；每次切换页面的 URL；卡点（作者停顿 > 60 秒、回读同一段落、报错）；每个提问原文；使用的 AI 工具与提示词摘要；是否用到 `AGENTS.md` / `AI_REFERENCE.md`。
- 通过：≤ 15 分钟到终点。15–30 分钟记为"完成但超时"；> 30 分钟或放弃记为"未完成"。

### 任务 2：面板或 CSV 导入器 + 打包安装（二选一，必做）

- 作者选择 React 面板模板（`--react`）或 CSV 导入器模板（`--importer`）之一。
- 面板：至少一个自定义状态与交互；**不使用宿主任何组件**，只用文档说明的主题变量 / 模板自带 `ui` 文件；主持人截图面板与宿主设置页并记录"是否视觉一致"（字体、圆角、颜色、深浅色跟随）。
- 导入器：能导入一份作者自己准备的 ≥ 3 行 CSV 并在画布看到笔记，随后用应用内回滚撤销。
- 打包与安装：`bun run test` 通过 → `bun run package` 生成 `.ghostboard-plugin` → 在应用 设置 → 插件 通过本地文件安装并启用 → 功能可用。不要求签名。
- 记录同任务 1；额外记录测试是否一次通过、打包输出文件名、安装预览显示的 ID / 版本 / `unsigned`。
- 通过：≤ 45 分钟完成安装并可用。

### 任务 3：签名与更新（可选，剩余时间允许时）

- 作者按 Distribution 页生成 key、签名、写 `update.url` 指向自己可控的 HTTPS 地址（GitHub Pages / Gist raw 均可），安装后发布 0.1.1 并在应用内检查更新。
- 只记录是否完成与卡点，不计入通过标准。

## 4. 卡点分类与处理

每条卡点在证据中按以下四类之一归档，并写明处理与负责批次：

| 类别 | 含义 | 处理 |
| --- | --- | --- |
| 文档修正 | 文档缺失、顺序不对、术语不一致、示例跑不通 | 改 `packages/plugin-docs-site` 内容或 `AI_REFERENCE.md`，本轮内提交 |
| 脚手架修正 | 模板、`create-ghostboard-plugin` 提示、`package.json` 脚本或 `AGENTS.md` 误导 | 改 `packages/create-plugin`，跑 `test:plugin-templates`，视影响发布 patch 版本 |
| 宿主 bug | 应用行为与文档不符、报错定位不到插件文件、安装 / 重载失败 | 建 issue，标注阻塞级别；阻塞任务 1 的宿主 bug 修复后必须第二轮 |
| 不改（写入限制） | 设计取舍（无沙箱、KV 无迁移、DOM 副作用不可撤销等）或超出首版范围 | 补进兼容策略 §6 / 文档站 Policy 页"限制"表，回复作者原因 |

第二轮触发条件：任务 1 有任一作者"未完成"，或两名以上作者在同一处卡点。第二轮至少 1 名新作者，用修正后的文档与脚手架重跑任务 1。

## 6. 输出

- 每位作者一份 §5 记录，去除个人身份信息后放入 [作者试用证据](trusted-plugin-t5-author-trial-evidence.md)。
- 汇总表：人数、任务 1 通过率与中位用时、任务 2 通过率、卡点按类别计数、修正提交列表、是否触发第二轮及其结果。
- 结论只允许三种：**达成**（≥ 2 名作者任务 1 通过且任务 2 通过）、**部分达成**（有作者超时完成，修正后第二轮达成）、**未达成**（第二轮后仍有作者任务 1 未完成）。未达成时 T5 不得退出，问题回流到 T5-1 / T5-3。
