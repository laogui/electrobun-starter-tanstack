> **来源**：结合 [docs/PRD.md](../../PRD.md) 当前 MVP 状态与 2025-2026 行业趋势分析，梳理出的可落地创意方向。
>
> **筛选原则**：每一项都必须能复用现有架构基础（`.md` 内容树 / per-view manifest / FLIP 动画 / Bun-RPC / Tiptap），避免推倒重来。

## 一、直接命中差异化亮点

### 1. 真正落地「语义化缩放」(Semantic Zoom) 🥇

> PRD §2.1 已写但未实现。这是 Muse / tldraw / Heptabase 都在打的牌，做透即可成为核心卖点。

**设计要点**

- `zoom < 0.3`：卡片只剩**色块 + emoji 图标**，靠空间位置形成「认知地图」
- `0.3–0.7`：标题 + 一行摘要（由 markdown-it 提取首段）
- `> 0.7`：完整正文 + 图片
- 档位过渡使用 spring 曲线，~180ms

**创新加分项**

- 在最低缩放档下叠加一层「**语义热力图**」——根据标签 / 连线密度生成柔和色斑，让用户在缩略视图下也能"看懂"知识地形
- 不同 `displayHint` (`note` / `checklist` / `image`) 在低 zoom 档位用不同图标符号区分

**实现切入点**

- `src/mainview/components/canvas/` 中的各 Card 组件按 `useStore(s => s.transform.zoom)` 切换渲染分支
- 抽出 `useSemanticZoomLevel()` hook 统一阈值

**预估复杂度**：中

---

### 2. 本地 RAG 语义搜索 + AI 命令面板 (`Cmd+K`) 🥇

> 你已有完整 `content/*.md`，天然适配 RAG。配合本地优先信仰，零云依赖即可上线。

**技术方案**

- **嵌入模型**：[Model2Vec](https://github.com/MinishLab/model2vec) 或 fastembed（纯 JS、~5MB），跑在 Bun 侧
- **向量库**：`.ghostboard/index.sqlite` + [sqlite-vec](https://github.com/asg017/sqlite-vec) 扩展
- **增量索引**：监听 `chokidar` 文件变更，仅重嵌入 dirty 文件，启动时全量比对哈希
- **混合检索**：BM25 (FTS5) + 向量 KNN，目标响应 < 30ms

**`Cmd+K` 命令面板（Generative UI）**

```
> 把所有提到 onboarding 的卡片聚到当前视口
> 总结这个 Group 里的卡片
> 找出与"产品定位"相关但没连线的笔记
> 创建 #meeting 卡片，参与者：张三、李四
```

- 解析层用本地小模型 + 规则；可选接 Ollama / OpenAI（开关在 PRD §6 已预留）
- 命令结果直接调用 Zustand action（如 `fitViewToNodes`、`createNode`），不绕远路

**预估复杂度**：高（但分阶段：语义搜索 → 自然语言查询 → 自动化操作）

---

### 3. 双向链接 `[[note]]` + Backlink 幽灵连线 🥈

> PRD 远期 #29 提前。你的 `noteId` 抽象本来就为此而生。

**设计要点**

- Tiptap 输入 `[[` 触发笔记 picker（基于已有标题模糊匹配 + 最近编辑排序）
- 解析 `.md` 时维护 `noteId → referencedBy[]` 反向索引（写入 `.ghostboard/backlinks.json`）
- 聚焦模式底部显示「被哪些笔记引用」列表

**创新组合：双层关系图**

- 显式 Edge = 用户主动绘制的视觉关系
- Backlink = 内容层隐式的语义关系
- 在画布上把 backlink 渲染为「**半透明虚影连线**」——默认隐藏，悬停某节点时所有隐式连接幽灵浮现
- `Cmd+Shift+L` 切换全局 Backlink 可见

**预估复杂度**：中

## 二、技术上独一无二（开发者人群破圈）

### 4. MCP Server：让 Claude Code / Cursor 读写画布 🥈

> Obsidian 1.12 刚走通的路，对你来说几乎免费——Bun 侧已有 RPC 协议。

**暴露的工具集**

```
ghostboard mcp serve
  → ghostboard_search(query)         // 语义检索
  → ghostboard_read_note(noteId)     // 读取笔记内容
  → ghostboard_list_canvases()       // 列出所有画布
  → ghostboard_create_card(canvasId, content, position?)
  → ghostboard_link_notes(fromId, toId, label?)
```

**杀手场景**

> 开发者在 Cursor 写代码时，让 AI 直接查阅他在 GhostBoard 上整理的设计规范、Bug 复盘、API 草图——这是 Notion / 任何云端方案永远做不到的（数据不出本机）。

**预估复杂度**：低-中（基本是把现有 Bun RPC 包一层 MCP 协议）

---

### 5. CLI 与 URL Scheme 摄入钩子 🥉

```bash
ghostboard quick "今天和老板聊的三个点..."          # 落到 Inbox 画布
ghostboard clip <url>                              # 网页剪藏 → 自动新建 Card
echo "$CLIPBOARD" | ghostboard add --canvas roadmap
ghostboard open note://note_a1b2c3d4              # 系统级深链
```

- 配合系统全局快捷键（PRD 远期 #26），实现「随时把闪念扔进画布」
- macOS 注册 `ghostboard://` URL scheme，可被任意 App 调用
- 比 Notion Quick Capture 更快、更不打扰

**预估复杂度**：低

## 三、认知科学 / 空间记忆向

### 6. 「悬浮标签」(Floating Tab) — Scrintal 杀手锏 🥉

- 在画布上**右键某节点 → "Float as Reference"**，该卡片以小窗钉在屏幕角落
- 用户继续平移/缩放主画布做笔记时，参考材料始终可见
- 支持多个 Floating Tab 自动堆叠/平铺
- 与 FocusedView 互补：FocusedView 是沉浸阅读，FloatingTab 是边读边记

**预估复杂度**：中

---

### 7. 「时间穿梭」画布 (Temporal Canvas) ✨

> 实现成本低，但视觉冲击极强，演示视频自带传播性。

**实现方案**

- `.ghostboard/snapshots/` 目录每天自动留 manifest diff（已有 manifest 抽象，零新数据结构）
- 顶部工具栏拖一个**时间滑块**，画布平滑"回放"到任意历史时刻
- 节点出现 / 消失 / 移动用平滑 FLIP 动画演示——像看自己思考的延时摄影
- 进阶：标记关键节点（"上线日"、"Review 会"）作为 anchor

**预估复杂度**：中

---

### 8. 演示模式 / Walk-through (Slideshow) ✨

> 把研究过程可视化输出，对学术、设计 review 场景极有杀伤力。

**交互流程**

- 选中若干 Edge 形成有向路径 → `Cmd+P` 进入演示模式
- 画布按 Edge 顺序自动 fitView 到每个节点
- 配合已有的 FLIP 动画 = 天然的「思路演讲」工具
- 方向键翻页，`Esc` 退出
- 可导出为 mp4 / GIF

**预估复杂度**：低-中（复用 fitView + FLIP）

## 四、补足现代 PKM 必备

### 9. 轻量级 Supertags / Schema 🔮

> 不必做成 Tana 那么重，作为 `displayHint` 的正交维度。

- frontmatter `tags: ["#meeting"]` 时，自动注入字段模板（参与者、行动项、决议）
- 画布上同 supertag 的卡片支持「**一键聚合视图**」：临时浮现一个表格视图列出所有 `#meeting` 卡片
- 表格列由 supertag schema 定义，可在 settingsview 中编辑

**预估复杂度**：中

---

### 10. Folder 子画布 + 卡片库 (Library) 🔮

> 升级 PRD §6.1 当前的 MVP 限制（Folder children 仅画布内可见）。

**升级路径**

- Folder 内部 = 一个独立子画布（递归用同一套 Canvas 组件）
- 子卡片获得独立 `.md` 文件 + `noteId`，外部编辑器可访问
- 同时新增 **「卡片库」(Library) 抽屉**：左侧栏列出所有 `.md` 笔记（含 unplaced），支持拖回任意画布
- 这就是 Heptabase「Card Library + Whiteboard」分离模型的本地优先实现

**预估复杂度**：高（需要重构 Folder 数据模型 + 迁移脚本）

---

## 一句话推荐

> 如果只能挑 3 个先做：**语义化缩放（差异化）+ 本地 RAG / `Cmd+K`（AI 时代门票）+ 时间穿梭画布（病毒式传播点）**。三者都能直接复用现有的 manifest / `.md` / FLIP 动画基础设施，几乎不需要重构架构。
