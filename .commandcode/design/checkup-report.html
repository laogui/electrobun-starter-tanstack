// WHAT'S WORKING

Intentional token + theme system

:root HSL group tokens, better-themes dark/light, canvas bg presets with dark fallback, isColorDark() flips card text. Not default Tailwind soup.

Comprehensive keyboard layer

useCanvasKeyboard: spatial Arrow nav + auto-center, Enter opens, Delete, clipboard, group/ungroup, undo/redo, zoom, Cmd+K search, type-to-search. Offsets disableKeyboardA11y.

Undo beats confirm

Node and view deletes emit a Sonner toast with Undo instead of a blocking confirm; only folder deletes confirm. The right split.

Zoomed-out legibility

CardNode swaps the full preview for a title + skeleton-bar layout at low zoom, keeping cards scannable instead of rendering unreadable tiny text.

Performance-conscious rendering

Node-identity cache avoids whole-canvas re-render each drag frame, rAF-throttled drag-over, isolation:isolate per node, hydration gate with Loader.

Strong empty/onboarding state

EmptyCanvasOverlay teaches the space (create / templates / library) with drop + create-menu hints, focus rings, and dark variants.

// PRIORITY ISSUES
P1

Low-contrast secondary text fails WCAG AA

text-gray-400 / neutral-400 (~#9ca3af) at text-[10px]-text-xs (10-12px) on white: ~2.8:1, below the 4.5:1 AA minimum. Found in titlebar kbd hint, view node-count, and search result meta + group count. gray-500 excerpt text is borderline-pass.

FIX: Raise every secondary text under 14px to gray-500/neutral-500 minimum (>=4.5:1), or bump size to >=14px. Audit across both themes; the light-theme pair is the failure.
P1

Spatial canvas has weak screen-reader semantics

The React Flow pane is not a labeled application/landmark and nodes carry no programmatic roles/labels a screen reader can traverse. disableKeyboardA11y + nodesFocusable= { false} removes the built-in focus chain; the custom key handler has no SR-equivalent announcements.

FIX: Wrap the pane in role="application" aria-label="Note canvas" + shortcut hint; add a polite aria-live region announcing selection/counts; keep search as the documented accessible path and surface it from the empty state.
P2

First-load keyboard entry point may strand users

Arrow nav calls selectNodeInDirection from the currently selected node; on a freshly hydrated canvas with no selection, arrows may have no anchor. Cmd+K, Cmd+N, and type-to-search still work, so users are not fully stranded.

FIX: On hydration, focus a logical first node or canvas landmark so arrow nav has a starting selection; add a ? / help affordance listing the keyboard map.
P2

Narrow-window behavior unverified

Bottom controls are fixed bottom-6 left-1/2 -translate-x-1/2; titlebar search is min-w-[14rem] max-w-md centered. No breakpoints guard these for narrow widths; chrome could crowd/overlap below ~700px while the canvas itself stays pannable.

FIX: Test at 600-800px width; clamp or stack the bottom cluster and titlebar search; ensure minimap/controls don't collide.
P2

Reduced-motion has no in-app control

index.css honors @media (prefers-reduced-motion: reduce) globally (good baseline), but there is no Settings toggle for motion preference.

FIX: Add a motion preference to Settings (None / Reduced / Standard) defaulting to the OS value.
P2

Runtime speed unverified

Code shows strong patterns (identity cache, rAF throttle, compositing isolation, hydration gate, devtools hidden until hover) but actual load time and pan/drag jank were not measured without launching the Electrobun build.

FIX: Run bun run dev:hmr on a large canvas (200+ nodes); check pan, drag, resize, and modal-open latency; watch for layout shift on hydration.
