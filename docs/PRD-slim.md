# GhostBoard 减法版 PRD（slim/v1）

> 基线：main `b4ec080`（2026-11-04）。本文只定义**这一阶段做什么、不做什么**；交互细节仍以 [PRD.md](./PRD.md) 对应章节为准。两份文档冲突时，范围以本文为准。

## 1. 一句话定位

**GhostBoard 是写东西之前的资料整理台：把网页、截图、文件和笔记摊在一张画布上对照，整理出结论，再导出成 Markdown 带走。**

本地、离线可用、中文友好、免费。

## 2. 先服务谁

**第一类用户：中文文字工作者。** 记者、特稿与非虚构作者、公众号 / 专栏作者、书评人、小说作者。共同点是动笔前要摊开大量资料：选题、采访、引述、事实核查、结构。（2026-11-04 修订，原为“学生和创作者”。）

- 第一号用户是开发者本人：下一次写作任务从头到尾只用 GhostBoard 完成，记录每个卡住的地方。
- 暂不同时服务：时间管理用户、插件开发者、团队协作用户。
- 获客渠道（验证用）：一篇稿子从选题到成稿的画布录屏（小红书 / B 站 / 即刻）、少数派、Obsidian 中文社区、写作者社群。
- 对标 Heptabase。差异只有一句：本地、免费、中文友好、专注“写作前”。

## 3. 唯一的核心流程

> 带入素材 → 浏览与编辑 → 分组与连线 → 找回 → 写结论 → 导出 Markdown

所有功能按这条流程判断：**在流程上的保留并打磨；不在流程上的隐藏或冻结。**

## 4. 保留、隐藏、冻结

### 保留（这一阶段的全部产品）

| 类别 | 内容 |
| --- | --- |
| 内容 | Note（BlockNote 长文）、Sticky、Topic（轻量导图）、图片、链接、文件 |
| 整理 | 连线、Group、Folder、标签、多画布、撤销重做 |
| 找回 | `Cmd/Ctrl+K` 搜索、笔记库 |
| 产出 | 侧边栏编辑（可切全屏写作）、AI 把选中资料总结进一张 Note、Markdown 导出 |
| 模板 | 深度稿素材板（首次打开即为它）、选题库、采访整理、拆书笔记、小说设定板、文章结构图、空白。源文件由 `scripts/templates/build_writer_templates.py` 生成 |

### 已删除的旧功能（2026-11-05，用户要求“隐藏改删除”）

原先只隐藏入口，现在代码一并删掉，`productScope.ts` 已不存在。旧数据在打开画布时自动转换，不丢内容：

| 项目 | 原因 | 旧数据怎么处理 |
| --- | --- | --- |
| 许可证卡片与 100 张免费额度（含 `license.ts`、激活 RPC） | 还没有用户，额度只会挡住试用 | 工作区里的 `license.dat` 不再读取 |
| 设置 → 画布类型（含按类型启用/停用） | 写稿用不到 | `.ghostboard/extensions.json` 不再读取，所有卡片类型都可用 |
| 7 个模板：快速上手、演示、看板、冲刺复盘、周计划、四象限、开一家店 | 不在写作流程上 | 用它们建好的画布不受影响 |
| 番茄钟、提醒（含定时调度） | 与整理资料无关 | 卡片显示“此卡片类型已移除，原始数据已保留”占位，可删除 |
| 录音（含麦克风录制） | 写作场景很少用 | 转成普通音频文件卡，指向同一个音频文件 |
| Checklist（含旧小组件体系 widgetStore / WidgetNode） | 由 Note 内任务列表替代（BlockNote 输入 `[]`） | 转成一张笔记，正文是同样的任务列表（`- [x]` / `- [ ]`）；旧“清单笔记”直接按普通笔记显示 |

### 冻结（不删代码，停止新开发，不对外宣传）

- 网站的 App、API 与登录（Google OAuth、Resend、Neon 相关）：官网只保留介绍与下载。
- 付费与订阅。

解冻条件：核心流程有一批真实用户在用，并且有人明确提出“需要扩展”或“愿意付费”。

### 删除（2026-11-05，用户决定）

- 插件系统整块删除：运行时、主进程宿主、SDK、脚手架、文档站副本、签名与授权、T0–T5 探针脚本、相关 CI 与设置页。原因：写稿的人不会装插件；它每次启动都要加载，带着无法补齐的同 realm 安全缺口，且只在 Mac arm64 上验证过。
- 插件顺带承担的“主进程笔记变更同步到画布”改为 `src/mainview/lib/noteChangeSync.ts`；统一撤销只保留画布、扩展实例两种来源（小组件已随 Checklist 等删除）。
- 旧数据：应用数据目录的 `plugins/`、`plugin-data/`、`plugin-permissions.json` 与工作区的 `plugin-migrations/` 不再读取，也不自动删除。

## 5. 下一步（按顺序）

1. **自己用一周**：用 slim/v1 完成一次真实写作，按 PRD §1.3 记录阻断点。已记下的第一个阻断点：卡片打开的全屏形变动画在 WebKit 下做不顺。决定改为**右侧边栏打开**（单击打开、选中只靠框选——用户 2026-11-05 改回；盖在画布上、不加遮罩），删除整套转场代码。先做侧边栏再自用，见 [remediation-plan.md](./remediation-plan.md)。
2. ~~**合并找回入口**~~（已完成）：游离笔记侧栏已删除，创建菜单的“文库笔记”和工具栏都打开同一个笔记库；游离笔记点一下即放回画布中央并打开，Unlinked Files 留在笔记库底部。找回入口只剩搜索和笔记库两个。
3. ~~**Checklist 并入 Note**~~（已完成）：可见模板全部改用 Note 内任务列表；2026-11-05 起 Checklist 卡已删除，旧清单打开时转成笔记。
4. ~~**标签简化**~~（已完成）：只剩一种标签，每个标签可单独设颜色。界面此前已合并显示；这一步把数据层的主标签 `tag` / `tagColor` 在读入时并入标签列表，不再写回。旧数据无损。
5. **评估 Group / Folder 合一**：Folder 作为 Group 的“折叠”状态，用户只需学一个分组概念。先写方案，验证后再动代码。**2026-11-05 用户决定：先不合并。**
6. **写一个对外演示**：用一篇稿子从选题到成稿的完整过程录屏，作为第一条获客内容。

第 5、6 步推迟到整改方案的方向决策之后。

## 6. 这一阶段不做

- 新的卡片类型、新的插件能力、新的动画变体。
- 网页剪藏、PDF 批注、Backlinks、移动端、多人协作。
- 任何以“功能清单更全”为理由的需求。新需求必须来自第 5 节第 1 步记录的真实阻断点。

## 7. 判断做对了

- 开发者本人能只用 GhostBoard 完成一次写作，中途不需要切到别的工具整理资料。
- 5 个目标用户试用后，至少 3 个能不看说明走完核心流程。
- 设置页和创建菜单里，每一项都能说清楚“它在核心流程的哪一步”。
