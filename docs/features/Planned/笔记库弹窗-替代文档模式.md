# GhostBoard 笔记库弹窗（Library Popup）— 替代文档模式

> **状态**：Planned　**优先级**：P1
> **前置决策**：移除现有双布局文档模式（LayoutSwitcher + DocumentView 全家桶）
> **关联**：[PRD.md](../../PRD.md) §2.12 布局模式、[旧文档模式 spec](../Backlog/双布局-文档模式.md)（归档）

---

## 1. 背景与动机

当前应用实现了「画布 / 文档」双布局模式（`LayoutSwitcher` + `DocumentView`），但存在以下问题：

1. **增加了产品复杂度**——双模式意味着双份交互逻辑、状态冻结规则、键盘快捷键映射，维护成本高
2. **与市面产品同质化**——文档模式（左栏目录树 + 右栏编辑器）本质上和 Notion / Obsidian 没有差异，无法成为 GhostBoard 的差异化卖点
3. **半成品状态**——目录树、拖拽排序、右键菜单等核心交互未实现，给用户留下「承诺未兑现」的负面印象
4. **稀释了 canvas-first 定位**——用户在两种模式间切换时会产生认知割裂

**决策**：移除文档模式，代之以轻量的「笔记库弹窗」，解决用户的**浏览式发现**需求（"让我看看我有什么"），同时保持画布作为唯一的核心界面。

---

## 2. 用户故事

1. 作为一个画布用户，我希望不离开画布就能快速浏览当前画布上的所有笔记，找到我想编辑的那一篇。
2. 作为一个拥有大量笔记的用户，我希望能按文件夹分组查看笔记，并通过搜索快速筛选。
3. 作为一个画布用户，我点击笔记库中的某篇笔记后，画布能自动飞到那张卡片并打开聚焦编辑。
4. 作为一个拥有 detached notes（未放在画布上的游离笔记）的用户，我希望能在笔记库中看到它们并放回画布。

**弹窗规格**：
- 尺寸：最大 `720px × 70vh`，居中
- 背景遮罩：`bg-black/40`，点击关闭
- 进出动画：`motion/react` 的 `scale(0.96) → scale(1)` + `opacity(0) → opacity(1)`，~200ms
- 可通过 `Escape` 关闭

### 4.3 笔记卡片

每张卡片展示：
- 类型图标（📝 Note / ✅ Checklist / 🖼️ Image / 📎 Asset / 🔗 Link）
- 标题（截断 2 行）
- 更新时间（相对时间）
- 卡片颜色条（若有 `data.color`）

### 4.4 分组逻辑

按以下顺序展示：

1. **Folder 分组**——遍历当前画布中所有 `folder` 类型节点，每个 Folder 作为一个分组，标题为 Folder 名称，内含其 `data.children` 中的 Card / Image / Asset / Link
2. **未分组**——不属于任何 Folder 的顶层 `card` / `image` / `asset` / `link` 节点
3. **游离笔记**（仅当存在时显示）——`data.detached === true` 的节点

Sticky / Group / Edge **不在笔记库中显示**。

### 4.5 排序

顶部提供排序切换（下拉菜单）：
- 最近编辑（默认）—— `updatedAt` 倒序
- 名称 A–Z
- 创建时间

排序在每个分组内部生效。

### 4.6 搜索筛选

顶部搜索框对标题进行即时筛选（前端 filter，不走后端 RPC）。输入时隐藏不匹配的卡片，空分组自动隐藏。

### 4.7 点击行为

| 场景 | 行为 |
| --- | --- |
| 点击**顶层笔记卡片** | 关闭弹窗 → `fitView` 飞到该节点 → 自动打开 FocusedView |
| 点击 **Folder 内的子笔记** | 关闭弹窗 → 打开该 Folder 的 drill-down → 聚焦到子卡片 |
| 点击 **detached note** | 关闭弹窗 → toast 提示「此笔记尚未放置在画布上」+ 「放到画布」按钮 → 点击后 `pinNoteToCanvas` 放到视口中心 → 自动打开 FocusedView |
| 点击 **Image 类型卡片** | 关闭弹窗 → `fitView` 飞到该节点 → 自动打开 FocusedView（图片预览模式） |

### 5.5 弹窗组件实现要点

```tsx
// LibraryPopup.tsx 核心结构
export function LibraryPopup() {
  const open = useCanvasStore((s) => s.libraryOpen);
  const toggle = useCanvasStore((s) => s.toggleLibrary);
  const { groups, detached } = useLibraryData();

  if (!open) return null;

  return (
    <AnimatePresence>
      <motion.div className="fixed inset-0 z-50 flex items-center justify-center">
        {/* 遮罩 */}
        <motion.div className="absolute inset-0 bg-black/40" onClick={toggle} />
        {/* 弹窗主体 */}
        <motion.div className="relative max-h-[70vh] w-full max-w-[720px] overflow-hidden rounded-xl bg-white shadow-2xl dark:bg-neutral-900">
          <LibraryHeader />
          <div className="overflow-y-auto p-4">
            {groups.map(group => (
              <LibraryGroup key={group.id} group={group} />
            ))}
            {detached.length > 0 && (
              <LibraryGroup key="detached" group={{ name: '游离笔记', items: detached }} />
            )}
          </div>
        </motion.div>
      </motion.div>
    </AnimatePresence>
  );
}
```

### 5.6 useLibraryData hook 逻辑

```ts
// 从 store nodes 派生分组数据
function useLibraryData() {
  const nodes = useCanvasStore((s) => s.nodes);
  return useMemo(() => {
    const folders = nodes.filter(n => n.type === 'folder');
    const groups = folders.map(f => ({
      id: f.id,
      name: f.data.title,
      items: (f.data.children ?? []).filter(c => ['card','image','asset','link'].includes(c.type))
    }));

    const folderChildIds = new Set(groups.flatMap(g => g.items.map(i => i.id)));
    const ungrouped = nodes.filter(n =>
      ['card','image','asset','link'].includes(n.type) &&
      !n.data?.detached &&
      !folderChildIds.has(n.id)
    );
    const detached = nodes.filter(n => n.data?.detached);

    return { groups, ungrouped, detached };
  }, [nodes]);
}
```

## 6. 视觉规范

- **卡片尺寸**：固定宽度 `152px`，高度 `auto`（标题撑开，约 `100–120px`）
- **卡片间距**：`gap-3`（12px）
- **网格**：`auto-fill, minmax(152px, 1fr)` 自适应列数
- **卡片样式**：`rounded-lg border border-border/50 bg-muted/30 hover:bg-accent/50 hover:shadow-md transition-all`
- **类型图标**：左上角小图标，14px，`text-muted-foreground`
- **颜色条**：卡片顶部 3px 色条（使用节点的 `data.color`，无色时不显示）
- **分组标题**：`text-sm font-medium text-muted-foreground`，前缀 📁 图标，括号内数量
- **弹窗圆角**：`rounded-xl`
- **暗色模式**：遵循现有 shadcn/ui dark 变量

## 7. 风险与权衡

| 风险 | 应对 |
| --- | --- |
| 移除文档模式后，现有用户（如果有）习惯被打破 | 产品尚在 alpha 阶段，用户量极少；文档模式本身是半成品，切换成本可接受 |
| 笔记库弹窗无法替代长文编辑场景 | 长文编辑由 FocusedView 承担，与笔记库是互补关系 |
| Detached notes 在弹窗中无法直接编辑 | 提供「放到画布」一键操作，放回后即可通过 FocusedView 编辑 |
| 笔记量大时（>200）卡片网格性能 | 首版用 CSS Grid + overflow-y-auto；若出现性能问题，后续接入 `@tanstack/react-virtual` |
| 删除大量代码可能引入回归 bug | 分两步执行：先删除文档模式（确认 CI 通过）→ 再新增笔记库弹窗 |
